# Теоретическая рамка: волновые структуры офсетинга декалей

Статус: справочная заметка (не задача). Источник обсуждения:
straight-skeleton offsetting с корректной топологией
(sthu.org/blog/14-skeleton-offset-topology) — вопрос пользователя
о возможностях, исключённых «туннельным зрением».

## Две канонические структуры

- **Distance field / Voronoi сегментов:** офсет = уровень поля
  расстояния; выпуклые углы — дуги (round joins). Наш
  Patch Voronoi — эта структура.
- **Straight skeleton:** рёбра волны движутся с равной скоростью,
  остаются прямыми; офсет = miter-семейство; скелет = полная
  compile-история топологических событий волны (схлопывания,
  расщепления) с точными высотами.

**Диагноз пост-фактум:** сага угловых багов (веер против хорды,
невидимая стена, пять итераций BEVEL) — конфликт двух структур:
столкновения считались в distance-field мире, эмиссия рисовалась
в skeleton-мире. RC5a закрыл это правилом; рамка объясняет
первопричину: miter/bevel-углы — граждане skeleton-структуры,
дуги/FAN — граждане Voronoi-структуры. Одна структура на
семейство join'ов — углы перестают быть патчем.

## Что берём (по слоям)

1. **I8 / CapacityPolicy:** высоты узлов скелета = доказанный
   предел покрытия региона -> `SATURATE_PROVEN` получает
   вычислимый критерий на compile (ревизия R1.9: план заранее
   знает ширину насыщения каждого региона).
2. **I1:** полная таблица событий офсета (слияния/расщепления,
   точные ширины) предвычислима — цель для plan-IR: «таблица
   высот событий»; drag только пересекает их.
3. **R2:** freeze-локус = дискретный cut locus дистанс-поля;
   RC1-конкуренция = встреча волн. Тестовый оракул:
   эквидистантность замороженной границы (RF7/RF17).
4. **R3:** лента на кривизне = ГЕОДЕЗИЧЕСКИЙ офсет seam-кривой по
   поверхности; rails — дискретные линии градиента геодезического
   поля; станции — накопленная длина. Рамка ВАЛИДИРУЕТ
   rail-архитектуру. Точные полиэдральные геодезики
   (MMP/window propagation) — кандидат-ОРАКУЛ КАЧЕСТВА для
   admission (G3-класс: мера отклонения станций от точной
   геодезической дистанции), НЕ поведение (поведение топологично).

## S4: ПОВЫШЕН из кандидата в целевой бэкенд (решение
обсуждения пользователь+исполнитель, поддержано ревью)

**`PLANAR_CORNER_SEEDED_SKELETON` — corner-seeded straight
wavefront.** Диагноз финализирован: дуги/параболы — не случайные
дефекты, а закономерный продукт евклидовой Voronoi-геометрии
(point-site ↔ segment-site = парабола) в задаче mitered-материи;
вся цепочка RC5/RC5a/RC5b/CAP-fan/TERMINAL_SITE_PAIR — попытки
научить Voronoi вести себя как skeleton. Гибрид пользователя
(«старт как Voronoi — доп. материя на острых углах; столкновения
как skeleton — без fan») реализуется так:
- CornerModel(V, P1, P2, join, owner, side) — ЯВНАЯ угловая
  ячейка в НАЧАЛЬНОМ условии волны (наследует топологическую роль
  Voronoi point-cell БЕЗ её параболической геометрии; границы —
  только прямые);
- дальше support-line propagation: collapse/split/meet события,
  прямые event-loci; MITER-апекс — естественная вершина волны,
  BEVEL-хорда P1-P2 — кинетическая грань, с которой сталкиваются
  чужие фронты;
- математическая легитимность гибрида — обобщение linear axis
  (разные начальные wavefront-паттерны на reflex/terminal
  вершинах — известная конструкция);
- Voronoi/SDF — оракул, witness, диагностика, будущий ROUND;
  production-граница — из CornerModel + straight wavefront;
- пост-процесс-фильтрация fan ОТВЕРГНУТА: фильтр удаляет лишнюю
  тесселяцию, но не превращает параболический СИЛУЭТ в прямой
  (это смена ownership/формы, не dissolve; плюс риск склейки
  owners/station ranges = новый слой эвристик; противоречит
  RM4-запрету пост-хилинга).
### Linear axis (Tanase & Veltkamp, ESA 2004) — замковый камень
corner-seeded подхода (находка пользователя)

Механизм статьи: начальный wavefront — ИЗМЕНЁННЫЙ полигон с
zero-length рёбрами, добавленными в reflex-вершинах; linear axis
— подмножество straight skeleton изменённого полигона;
epsilon-эквивалентность медиальной оси достигается вычислимым
числом вставок. Для нас это формализация corner-seeding и
УНИФИКАЦИЯ всех join'ов одним параметром начального условия:
- k=0 вставок -> MITER (апекс);
- хорда P1-P2 как начальное ребро -> BEVEL;
- k zero-length рёбер -> ROUND_k — полигональная дуга с
  КОНТРОЛИРУЕМОЙ плотностью (k — семантический счётчик класса
  «bevel segments» в Blender, I3-легален); k -> inf — медиальная
  ось/Voronoi-дуга.
Следствия: (1) три join-стиля = один кинетический движок + один
параметр сидинга, никаких отдельных структур; (2) столкновения
ВСЕГДА прямолинейные skeleton-события — парабол не существует ни
в одном режиме (идеал пользователя «старт как Voronoi,
столкновения как skeleton» — буквально linear axis); (3) fan
перестаёт быть дефектом — становится управляемым ROUND_k;
(4) CGAL-оракул работает для ВСЕХ join'ов: изменённый полигон —
валидный вход CGAL SS. Что остаётся нашим: обобщение на открытые
сети/two-sided/ownership; детерминированная конструкция вставок
(точная бисекция веера — геометрия из семантических входов, не
выбор); epsilon-машинерию статьи НЕ используем для авто-подбора k
(это был бы числовой тюнинг — k только семантика).

### Medial Skeletal Diagram (arXiv:2310.09395) — принцип
«редкий скелет + выразительные envelope» (находка пользователя;
принят с поправкой ревью о двух скоупах)

Принцип MSD: вместо множества простых дискретных
skeleton-элементов — МАЛО элементов, каждый с выразительным
непрерывным enveloping-примитивом (directional radius); форма =
union примитивов. Для CFTUV скелет ВООБЩЕ НЕ вычисляется — он
задан пользователем (seams/spine graph): берём только forward-
представление. Соответствие: medial vertex ~ Corner/Cap/Pole
primitive; medial edge ~ StripEnvelope; medial triangle ~
Junction/sector; directional radius ~ width/join/cap профиль;
union ~ материя декали.

**Главный вывод разбора — РАЗДЕЛЕНИЕ COVERAGE и OWNERSHIP** (что
существует vs кто владеет). Приинят С ПОПРАВКОЙ РЕВЬЮ — у вопроса
ДВА скоупа с разными канонными ответами:
- **ВНУТРИ одного компонента декали:** принцип верен полностью —
  материя = union примитивов ленты; внутренние ownership-границы
  (UV/станции/provenance) НЕ имеют права формировать силуэт.
  Полевое доказательство уже есть: вся сага «парабола в силуэте»
  и «дуга в пустоте» — внутрикомпонентные ownership-границы,
  протёкшие в coverage; RC5b (обоюдное прибытие) — точечный
  частный случай этого разделения, доказанный полем.
- **МЕЖДУ компонентами/потоками:** конкуренция ЛЕГАЛЬНО формирует
  материю — встречные декали делят территорию freeze-границей
  (RC1-RC3, RF7 — продуктовая семантика trim-листов, не дефект).
  Union разных декалей ЗАПРЕЩЁН (перекрытие = z-fighting).
Уточнённый вопрос гейта: не «нужна ли конкуренция для материи
вообще», а «подтверждается ли, что ВНУТРИ компонента достаточно
union+ownership, а конкуренция остаётся только межкомпонентной».

**Envelope-модель — во многом ПОВЫШЕНИЕ существующего, не новая
стройка:** A10-стрипы (две supporting lines) = StripEnvelope;
CornerModel (V/P1/P2) = CornerEnvelope; капы = CapEnvelope.
Генеалогически новые части: (1) exact union примитивов как
ЕДИНСТВЕННЫЙ источник силуэта компонента; (2) arrangement
понижается до ownership-разбиения ВНУТРИ покрытия; (3)
JunctionEnvelope — один семантический регион вместо fan of faces
(число runtime-граней — не часть определения; тесселяция —
downstream, semantic coalescing только при совпадении
owner/UV/station/provenance — дисциплина RM4).

**Снижение главного риска S4:** полный generalized kinetic solver
может не понадобиться как производитель формы: на каждом alpha
envelope-границы аналитичны и аффинны по alpha -> exact planar
arrangement/union даёт материю; кинетическая машина остаётся для
compile-static event-ledger (I1: интервалы alpha между событиями,
быстрый drag) и межкомпонентной конкуренции. Риск робастности
сжимается с «kinetic engine для всего» до «аналитические
примитивы + планарный arrangement (наша обкатанная территория) +
ограниченный event-ledger».

**Ограждения (из самой MSD и ревью):** топология union в MSD не
гарантирована (перекрытия примитивов) -> у нас ОБЯЗАТЕЛЕН путь
union -> exact arrangement -> уникальный ownership ->
GeometryBatch, без residual-перекрытий; «один hidden edge ==
BEVEL» НЕ принимается по определению — BEVEL определяется
продуктовым семантическим контуром V/P1/P2, hidden-front легален
только если доказано, что порождает именно его; performance
arrangement-per-frame решается event-интервалами (комбинаторика
стабильна между событиями — I1).

**Гейт волновых бэкендов расширяется до ТРЁХ моделей планарного
пути:** A — текущий PatchVoronoi (базлайн/оракул); B —
corner-seeded kinetic wavefront; C — envelope union + отдельный
ownership (+ kinetic только как event-ledger). Сравнение по
метрикам S-ENV0-списка (силуэт без sampled-парабол, число
semantic/materialized вершин, точная ширина, непрерывность
UV/ownership, столкновения, насыщение, инвариантности, итоговая
3D-геометрия).

### Ревизия ландшафта библиотек SS (веб-ресёч по запросу
пользователя; ПОПРАВКА ревью: «готовой библиотеки нет» — слишком
сильно. Точная формулировка: нет библиотеки под НАШУ постановку —
открытые seam-сети, corner-seeded старт, two-sided фронты,
барьеры, provenance/станции; все найденные работают с ЗАКРЫТЫМИ
полигонами. Но экосистема даёт ядра, оракулы и референсы):
- **CGAL Straight_skeleton_2** — промышленный эталон: exact
  predicates, WEIGHTED skeletons (с 2023) и skeleton extrusion;
  closed weakly-simple polygons + holes; C++/GPL (для
  Blender-аддона GPL не проблема — аддоны сами GPL; боль —
  сборка бинарей на платформы).
- **pySVCGAL** (PyPI) — CGAL SS-обвязка, созданная ДЛЯ Sverchok
  (мир прототипа пользователя!), активна 2024-2025,
  offset/extrude ноды, ставится pip'ом из Blender — путь
  дистрибуции CGAL в Blender уже протоптан сообществом; тот же
  класс optional-зависимости, что наш pyvoronoi.
- **bpypolyskel** (prochitecture) — Blender-нативный форк
  polyskel для крыш blender-osm: прогнан на 320k крышах OSM,
  99.99% успех; pure Python + mathutils. НО робастность — через
  пост-кластеризацию точек (скрытые epsilon: наш I3 потребует
  ревизии) и только closed polygons.
- **Botffy/polyskel** + производные (shapely-polyskel,
  ladybug-geometry-polyskel) — базовый Felkel-Obdržálek;
  известные точностные проблемы.
- **Lichtso/straight_skeleton** (ссылка пользователя) —
  Blender-аддон pure Python по работам Huber/Held; GPL-3, 9
  коммитов, один полигон за раз — читаемый учебный референс
  Huber-подхода прямо в Blender, не production.
Три стратегии использования (не взаимоисключающие):
(A) **Оракул немедленно**: CGAL/pySVCGAL/bpypolyskel как эталон
    событий/офсетов на планарных фикстурах (заменить
    py_straight_skeleton спайка на CGAL-backed референс);
(B) **Ядро для закрытых поддоменов**: клипнутый доменом band на
    планарном патче — замкнутый полигон; interior (weighted) SS
    от CGAL применим к части задачи (ownership/two-sided —
    нет);
(C) **Своя kinetic-волна поверх НАШИХ структур** (станции,
    event-heights, CornerModel) — референсы алгоритмов:
    Felkel-Obdržálek (прост, хрупок), Huber/Held motorcycle
    graph (быстрее, стабильнее), CGAL (эталон корректности).

Ограждения ревью: (1) кинетическая волна с событиями — самый
робастность-требовательный класс вычислительной геометрии
(одновременные события, параллельные рёбра, вырожденные
коллапсы): детерминизм, I3-честные guard'ы, бит-стабильный
порядок событий — обязательные приёмочные критерии; готовой
библиотеки нет (CGAL — только замкнутые полигоны; Boost.Voronoi
не делает SS). (2) Миграция ТОЛЬКО поэтапная: дизайн event-модели
-> прототип-оракул рядом с PatchVoronoi (differential по
S0-паттерну, тот же GeometryBatch) -> переключение маршрутизации
по полевому доказательству; PatchVoronoi остаётся
сравнительным оракулом. (3) До старта S4 планарный путь — в
maintenance mode: НОВЫЕ семантические патчи RC5-семейства
запрещены (только именованные fail'ы); лечение парабол локально —
прекращено. (4) Event-словарь (WavefrontEvent/высоты) — ОБЩИЙ с
кривизной: два бэкенда (PLANAR_SUPPORT_LINE, SURFACE_GEODESIC)
под одним IR-контрактом — не проектировать модель событий дважды.

## Дополнение по двум внешним разборам (приняты с правками)

### Три разных «оффсета» — окончательное разделение задач
1. **Ширина ленты по поверхности** = intrinsic geodesic distance
   d_S(p, seam) — территория wavefront/rails.
2. **Отрыв от поверхности** (`decal_offset`, анти z-fighting) —
   extrinsic lift; здесь ambient 3D SDF ЛЕГАЛЕН как валидатор
   зазора: error(v) = |SDF_owner(v) - decal_offset|
   (owner-constrained поле, иначе «ближайшей» окажется чужая
   стена). ПОПРАВКА к прежнему полному отказу: волюметрический SDF
   отвергнут для ШИРИНЫ/покрытия, но принят как
   диагностика/валидатор lift. Как замена lift'а — нет (евклидов
   shell скругляет архитектурные рёбра; текущий
   offset-plane-intersection = HARD_MITER-shell; SDF-shell —
   возможный будущий ROUND_SHELL режим).
3. **Материя углов** (join) — CornerModel; поле НЕ выбирает
   join (евклидово утолщение полилинии даёт round caps — это
   семантика будущего ROUND, не MITER/BEVEL). Зависимость строго:
   join policy -> CornerModel -> аналитическое поле модели.

### Labeled distance witness (2D-аналитический слой; принят)
Голый скаляр расстояния бесполезен для CFTUV — нужен СВИДЕТЕЛЬ:
`DistanceWitness2D` (distance, closest_point, gradient, site_id,
side, source_parameter, source_s, feature_kind) и
`DistanceCompetition2D` (первый/второй кандидаты, margin;
equality-локус материализуется геометрически, margin — значение
поля и диагностика, НЕ `abs(margin)<eps`-ветвление). Это
формализует (s, r)-контракт и уже существующую семантику
`segment_point_distance2()`. Предостережения (приняты):
- растровый SDF + marching squares как источник topology —
  ОТВЕРГНУТ (2/10: resolution-зависимость, saddle-неоднозначности,
  скрытые epsilon, preview != confirm);
- после min/max композиции поле — pseudo-SDF: знак и нулевой
  контур верны, magnitude/градиенту доверять нельзя (не
  офсетить повторно, не мерить ширину); хранить примитивные
  witnesses;
- open seam не имеет глобального знака: unsigned distance +
  явный BandSide + owner-domain sign, никакого глобального
  signed поля для T/X-сетей;
- поле — слой ЗАПРОСОВ, не полигонизатор: точную topology
  по-прежнему даёт vector arrangement.
Применения по убыванию ценности: независимый оракул ИТОГОВОЙ
геометрии (семплировать материализованные faces против
intended-поля — прямое лекарство от Б5); (s,r)/UV provenance;
валидация CornerModel (утечка за хорду, остаточный апекс);
конкуренционная диагностика; GPU debug (шейдер читает ТЕ ЖЕ
модели, что CPU — иначе Б1); будущий ROUND join (для него
евклидово поле — родная семантика).

### SurfaceWavefrontIR и вопрос-гейт перед R3 (принят как гейт)
Целевая абстракция: compile-static объект
{sources, barriers, cells(owner, side, s-range, arrival model,
provenance), events(alpha, kind, participants, locus),
cut_locus, max_proven_width} с двумя бэкендами под одним
контрактом: PLANAR_SUPPORT_LINE (skeleton-семейство, miter) и
SURFACE_GEODESIC (интринсик-распространение). НЕ
vertex-sampled текстура (иначе Б1: массив расстояний отдельно,
ownership отдельно).
**Вопрос-гейт перед R3 (обязателен к решению пользователем по
данным спайка):** должны ли rails на ГЛАДКОЙ кривизне оставаться
путями рёбер меша, или стать характеристиками интринсик-поля
(через интерьеры треугольников)? Аргумент за пересмотр —
обобщение НАШЕГО ЖЕ RP1: «топология меша в плоскости не несёт
геометрической информации» — на гладкой кривизне рёбра ниже
fold-порога суть артефакт тесселяции, и edge-only rails запекают
триангуляцию (две диагонализации сферы -> два разных русла).
Предикат уже есть: fold-порог разделяет «ребро = геометрия»
(fold -> edge-rail) и «ребро = шум тесселяции» (гладко ->
характеристика). Инструменты точные и детерминированные
существуют (window propagation / MMP-семейство). Решение — не
верой, а спайком S-WF0.

### Спайки (без production-маршрутизации)
- **S-DF2-lite** — внутри приёмки S-CM.a: witness-запросы +
  polygon-поле CornerModel + семплирующий оракул итоговой
