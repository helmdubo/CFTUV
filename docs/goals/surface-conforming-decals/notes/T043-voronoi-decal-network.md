# T043 — Seam decal network: α-clipped nearest-branch partition

Manual `Decal Seams` переведён с последовательности «независимые ribbons →
junction cut → радиальные сектора → dissolve поперечных рёбер»
(T035/T037/T039/T042) на единое глобальное разбиение по образцу
segment-Voronoi (Johannsen, Edge Decal Generator), адаптированное для
многоповерхностных corner-сетей. Новый модуль — `cftuv/decal_network.py`,
чистая геометрия без bpy/bmesh.

## Ключевые решения

- **Внутренняя метрика вместо 3D.** Постоянная ширина декали — геодезическое
  расстояние; corner из планарных owner surfaces изометричен плоскости.
  Partition считается в 2D на каждой owner offset-плоскости, лифт в 3D —
  отдельный слой (offset вдоль normal, corner spine на пересечении
  offset-плоскостей, junction core как least-squares, `_lift_position`).
- **Не полная Voronoi-диаграмма, а α-clipped ячейки.** Ячейка ветви =
  α-полоса вокруг spine ∩ полурегионы «ближе ко мне». Прямой клиппинг faces
  имплицитной функцией f = d_other − d_own (bisection по рёбрам + уточнение
  хорд по sagitta) вместо sweepline-ядра — робастно и достаточно, потому что
  вход ограничен mesh edges и малой валентностью junction.
- **Сайты — ветви, не сегменты.** Внутри ветви поперечные границы не
  возникают по построению. Коллинеарные продолжения в junction
  (`DECAL_NETWORK_CONTINUATION_DOT`) сливаются в сквозной сайт: непрерывный
  UV через узел, критерий геометрический, «главная ветка» не выбирается
  произвольно.
- **Ghost-сайты через fold не нужны.** Любой путь с соседней поверхности
  пересекает fold-линию; если fold выбран как ветвь, его spine всегда
  строго ближе. Per-surface сайтов достаточно — это доказуемо, а не
  эвристика.
- **Ties в общих vertex regions** двух ветвей, оканчивающихся в одном узле,
  разрешаются retraction обеих spine на δ ≪ weld: tie-регион схлопывается в
  угловую биссектрису (усреднённая divider-линия T039 получается как частный
  случай), имплицитная функция получает чистую смену знака.
- **Сшивка водонепроницаема по построению**: spine-станции и junction cores
  идут через единый registry по source vert index (`('sv', vert)` ключи),
  общий для крыльев на разных поверхностях. Разрез ячейки fold-линией не
  нужен — сайты каждой поверхности уже заканчиваются на её spine.
- **Смена поверхности внутри ветви** режет сторону на maximal подпути;
  на станции разреза добавляется connector-треугольник (аналог legacy
  BEVEL); почти копланарные разрезы схлопывает финальный weld.
- **Round caps на α** закрывают reflex-угловые промежутки junction
  (pac-man дыры legacy-пайплайна) и делятся биссектрисами между соседями.

## Результаты на fixtures (tests/test_decal_network.py)

- Planar T: ровно 6 faces; стем доходит клином до узла, divider-вершины
  (±α, −α); UV bar непрерывен сквозь узел; поперечное endpoint-ребро stem
  отсутствует по построению (T042 — частный случай).
- X-junction: 8 faces, партиция диагоналями, оба bar UV-непрерывны.
- Trihedral: общий offset core на всех трёх поверхностях, fold-спайны
  сшиты общими вершинами, round caps на расстоянии α от core.
- Близкие параллельные швы: клип по средней линии, u_frac отражает
  реальную ширину половины.
- Замкнутое кольцо: 8 faces, miter-станции, wrap без щели.

## Интеграция

`_fill_manual_chain_decals` (SEAMS + Edge Select) вызывает
`build_seam_network_faces`; `_materialize_network_faces` кладёт faces в
bmesh с shared вершинами по ключам. Legacy miter/junction pipeline сохранён
целиком как fallback: настройка `decal_seam_network` (панель, default ON)
и автоматический откат при исключении/пустом результате. Unpaired
boundary edges остаются на `_build_boundary_wing_strip`.

Полный suite: `74 passed` (56 legacy + 18 network).

## Follow-up: артефакты на дуговой стене (production repro)

Пользовательская сцена (дуговая стена с толщиной: cap-кольцо, торец,
вертикальное ребро) дала веер перекрывающихся треугольников на corner
junction и плоские «флаги» по касательной. Два независимых бага:

1. **Инвариантность convexity.** `reversed_copy`/`swapped_copy` у
   `_OrientedCornerRun` (и зеркально у `_NetworkBranch`) негировали
   `segment_convexities`. Dihedral convexity — геометрический инвариант
   фолда: flip-логика `_corner_wing_directions` симметрична и к развороту
   направления, и к порядку normals при неизменной convexity. Негация после
   stitch-разворота выворачивала крылья наружу меша («флаги») — латентный
   баг и legacy corner pipeline тоже. Негации удалены; знак задаётся один
   раз при создании run из boundary-oriented обхода side-A chain
   (`_manual_edge_pair_convexity`).
2. **Ограниченные junction caps.** Безусловная 90° дуга vertex region на
   каждом junction-конце висела за границей меша на поверхностях, где у
   узла нет углового соседа (торец), и давала «пинвил» из полуобрезанных
   вееров. Теперь cap строится только до биссектрисы с угловым соседом на
   той же поверхности: промежуток γ > 180° закрывается дугой γ/2 − 90°
   (красная схема T039), γ ≤ 180° закрыт самими полосами, одиночный сайт
   получает плоский конец (поведение legacy).

Регрессия: `TestOrientationInvariance` (reverse/swap дают идентичную
геометрию), `TestArcWallCorner` (ни одна вершина не выходит за меш; у
junction нет неограниченных вееров), `TestSingleSiteJunctionCap`.

3. **Локальные surface spans.** Разбиение стороны ветви на подпути шло по
   global greedy-match surface registry: на пороговой тесселяции (соседние
   нормали около `DECAL_COPLANAR_DOT`) surface id мог флип-флопить между
   почти совпадающими registry-плоскостями, рубя сторону на per-station
   подпути — flat caps и connector-треугольники на каждой станции читались
   «зубцами» вдоль внешнего радиуса дуги. Теперь span растёт по бегущему
   среднему нормалей + проверке принадлежности плоскости
   (`_side_surface_spans`); registry используется только для identity
   поверхности (общие 2D-миры у junction). Бегущее среднее одновременно не
   даёт транзитивно схлопнуть пологую дугу в одну хорду
   (`TestSurfaceSpans`).

Offline-репро с реальной сцены: `artifacts/dump_seam_scope.py` — дамп
selected seam scope (рёбра, вершины, нормали и центры смежных faces) в
JSON для переигрывания сети вне Blender.

## Follow-up 2: boundary-сайты и динамические oracle-тесты

По внешнему ревью зафиксировано требование: ширина α меняет не только
координаты, но и комбинаторику crop-сетки — M(α) = VoronoiCell ∩
Offset(branch, α). Kernel уже устроен как «evaluate at α» (полная
пересборка клиппинга на каждом вызове, включая каждый шаг modal drag),
и это теперь доказывается oracle-тестами `TestDynamicTopology`: тест
обязан провалиться, если сигнатура топологии (число faces, размеры
полигонов, число вершин) не меняется во всём диапазоне α:

- касание двух несвязанных параллельных ветвей на α = d/2 (staggered,
  появление midline-вершин);
- кривая point-vs-segment граница: ≥3 неколлинеарных equidistant-вершин
  (парабола отслежена уточнением хорд, а не одной хордой);
- острый V: round join за miter-лимитом, α-зависимая дискретизация дуги,
  ячейка ограничена 4α (без длинного шипа);
- короткая ветвь T: за критической шириной ячейка stem сжата бисекторами
  до длины ветви, а не α;
- boundary wing + соседний шов: общий divider без общей source-вершины;
- то же событие через выбранный fold: порог совпадает с планарным
  (бисектор на d/2), лифт водонепроницаем, крыло на второй поверхности
  события не видит.

Замечание о масштабной самоподобности: V-junction сам по себе не имеет
width-события — угловое отсечение самоподобно при масштабировании α;
событtopology возникает только при столкновении с другим масштабом длины
(miter-лимит, длина ветви, абсолютный допуск дуги/сварки).

Boundary edges переведены из legacy-крыла в полноправные односторонние
сайты сети: `_group_boundary_runs` собирает их в oriented runs по порядку
обхода side-chain (нулевая сторона A — маркер односторонней ветви; wing =
n × t; из continuation merge исключены, чтобы reverse не разрушал
ориентацию крыла). Legacy fallback сохраняет прежние посегментные крылья.

## Follow-up 3: конформный лифт span-чартов (production dump)

Пользовательский дамп (`cftuv_seam_dump.json`: ширина 0.7427, offset 0.001,
дуга ~5°/грань) воспроизвёл «зубцы» точно: chart span'а — усреднённая
плоскость 2–3 граней, и лифт через плоскость чарта клал ленту на хорду.
При offset на порядок меньше стрелки прогиба хорды лента протыкает
гранёную стену, углы flat caps выпирают наружу на ~0.015, а
connector-треугольники читаются зубцами вдоль внешнего радиуса.

Исправление — `_Site.to_3d`: чарт остаётся усреднённым (метрика клиппинга,
бисекторы), но каждая вершина поднимается аффинно во frame ближайшего
СЕГМЕНТА — на offset-плоскость реальной грани (станции точны через lift
registry, ширина вдоль грани — точно α). На production-данных лента легла
на стену (все вершины на offset-плоскостях своих граней), connectors у
почти-вертикальных боковых выродились и сварились. Дополнительно рост
span ограничен и первой нормалью span (дрейф бегущего среднего не
склеивает дугу сверх порога). Регрессия: `TestConformalLift` — встроенный
production-дамп, каждая вершина wall-ленты обязана лежать на
offset-плоскости какой-то реальной грани (< 2e-3). Полный suite:
`88 passed`.

## Follow-up 4: shared rail на смене поверхности (локальная развёртка)

По внешнему ревью: смена owner surface внутри ветви — общая fold-станция
внешнего rail, а не два flat-cap конца с connector-треугольником.
`_bridge_split_stations`: соседняя грань разворачивается вокруг fold-оси
(axis ∥ n_B × n_A, поворот Родригесом n_B → n_A — единственный и
корректный для любой выпуклости), offset-контуры пересекаются в
развёрнутой паре, единая miter-вершина складывается обратно в свой
столбец грани (сторона fold-линии определяется по точке строго внутри
развёрнутой полосы B — тангенс + крыло, невырожденно и для поперечного,
и для продольного fold). Оба сайта ссылаются на один vertex key
`('rail', branch, side, vert)`; connector-треугольник остаётся только
fallback'ом для вырожденной развёртки или miter за лимитом. На
production-дампе: rail-вершины на стене и на caps вместо connectors,
18 faces, все вершины на реальных гранях. Продольный fold (L-переход
пол→стена) получает поворот с постоянной шириной вокруг ребра — как
legacy corner miter, но с топологической сшивкой.

## Follow-up 5: жёсткие junction caps (MITER по умолчанию)

Reflex-промежутки junction закрывались округлой дугой радиуса α
(`_junction_cap_sweep` → `_arc_points`), полилинизация которой давала
видимый веер треугольников на многовалентных углах — художественно
нежелательно, где ожидается жёсткий стык. Политика вынесена в
`DECAL_NETWORK_JUNCTION_CAP_STYLE`:

- **MITER** (по умолчанию): reflex-промежуток закрыт одной общей вершиной
  на биссектрисе с угловым соседом, на радиусе α/cos(sweep) — та же
  биссектриса T039, но с одной жёсткой вершиной вместо дуги. За
  miter-лимитом (`DECAL_CORNER_MITER_LIMIT`) — прямой bevel до
  биссекторной точки на α, а не длинный шип.
- **ROUND**: законсервированная округлая дуга (прежнее поведение), для
  случаев, где округление желаемо.

`_junction_cap_outer` — общий helper обеих станций (порядок точек под
конвенцию сборки quad). На кубическом углу два перпендикулярных крыла
дают reflex 270°, sweep 45°, miter на α·√2 — диагональный внешний угол
(trihedral fixture: 24 → 12 faces, веер исчез). Планарный T, X, кольцо и
близкие параллельные не затронуты (их станции — convex miter или
concave-обрезка, не reflex cap). `TestJunctionCapStyle` проверяет, что
ROUND-ветка сохранена и переключается. Полный suite: `91 passed`.

## Follow-up 6: производительность (drag + клиппинг)

Профиль на плотной сети (дуга-гребёнка) показал: 97% времени —
клиппинг (`_clip_polygon` → `implicit` → `competition_distance`), причём
стоимость это миллионы мелких векторных операций в чистом Python, а не
«тяжёлая математика». Пространственная сетка сделала хуже (dict/set
overhead > экономия на коротких полилиниях). Реальная причина: для каждого
конкурента клипались ВСЕ полигоны сайта, включая далёкие, а ранний выход
`_clip_polygon` всё равно тратил вызовы `implicit`, сканирующие весь спайн
конкурента.

Два безопасных рычага (без сторонних зависимостей):

- **Polygon-vs-competitor bbox gate.** Полигон P режется конкурентом C
  только если его точка ближе к C, чем к своему спайну; макс. расстояние
  точки band до спайна — α·MITER_LIMIT, поэтому при
  `bbox_distance(P, C) > α·MITER_LIMIT` клиппинг пропускается целиком, без
  единого `implicit`. Масштабируется: 1.3× (мелкие) → 2.4× (SEGS=160).
  Всегда включён; differential-тест (`_gate=True` vs `_gate=False`,
  точное сравнение координат/UV на дуге и production-дампе для набора
  ширин) доказывает эквивалентность, а не просто непустоту.
- **Preview-клип для modal drag.** `build_seam_network_faces(preview=True)`
  не уточняет криволинейные point-vs-segment границы хордами. Контракт:
  preview может быть ГРУБЕЕ (меньше вершин), чем финал — это ожидаемо;
  финальная генерация (LMB/Enter, preview=False) полностью заменяет
  геометрию точной, допустим небольшой визуальный скачок. +~1.2×. Оператор
  строит preview во время drag, ESC восстанавливает базовую геометрию.

Дополнительно — scalar squared-distance kernel. `competition_distance_sq`
считает квадрат расстояния скалярной арифметикой по предвычисленным
плоским записям сегментов (`ax, ay, dx, dy, inv_len_sq`, retraction
встроена), без создания tuple в горячем цикле; `competition_distance`
берёт из него `sqrt`. Основной выигрыш — устранение миллионов tuple, а не
отмена sqrt (замер: sqrt-на-вызов стоит ~2%). Поэтому `implicit` использует
именно МЕТРИЧЕСКУЮ разность `d_other − d_own`, а не квадратичную: `keep_eps`
в клиппере имеет размерность длины, и сравнение с `d²`-разностью сделало бы
epsilon-зону вокруг нулевой линии масштабозависимой (сдвиг слияний вершин).
Так путь бит-идентичен коду до оптимизации, а быстрый кэш проверяется unit-
тестом против наивного расстояния. Замер: ~4× (SEGS=40: 1266 → ~300 ms;
кумулятивно от исходного ~1700 → ~300 ms, ≈5–6×). Относительный допуск
bisection (1e-12 → weld) отклонён: выигрыш ~1.2× сдвигал пересечения в
precision-чувствительных dynamic-topology тестах.

Итого для drag на крупных сетях ≈ до 3× относительно pre-оптимизации сети.
Оговорка: замеры — kernel-only, БЕЗ BMesh/`remove_doubles`/пересоздания
объекта/обновления viewport; следующий профиль нужно снять из modal-
оператора прямо в Blender. numpy пока не оправдан (последовательные
адаптивные запросы; много мелких numpy-вызовов могут быть медленнее). Тесты
`TestPerformancePreview` + `test_seam_modal_confirm_rebuilds_last_drag_at_full_precision`.
Следующие рычаги при необходимости — операторный слой (in-place mesh update,
defer `remove_doubles`), segment-block index, либо partition-cache для drag
(требует ширино-независимого junction-retract).

Известные приближения относительно полноценного planar arrangement (по
ревью — честные tradeoffs, а не ошибки): двойные пересечения ребра ловятся
8-точечной выборкой; общие кривые границы двух ячеек дают T-вершины с
зазором ≤ sagitta-допуска (закрывается weld). Конкуренция через
НЕвыбранный fold вне контракта данных producer (не видит меш) — потребует
расширения analysis-слоя (ghost-сайты, phase C). Кэш статического слоя
(развёртка+сайты) для drag — возможная оптимизация, на корректность не
влияет. Полный suite: `86 passed`.

## Follow-up 7: профиль детализации стыков (LOW по умолчанию)

При наложении лент угловые стыки давали дугу из десятков вершин. Источник
оказался не только `_refine_chord` (кривая клип-биссектриса), но и —
главным образом — `_station_outer_points`: острый convex-поворот за
miter-лимитом закрывался round-join через `_arc_points` (напр. 15 вершин
на 179°). Оба пути теперь подчинены единому профилю
`DECAL_NETWORK_CLIP_CURVE_STYLE`:

- **HARD** — прямой bevel/хорда без внутренних вершин;
- **LOW** (по умолчанию) — грубая дуга: допуск `max(weld, α·relative)` +
  жёсткий бюджет вершин на кривую (`_profile_arc` пересэмплирует в ≤ budget
  сегментов). Плотность одинакова на декалях любого размера;
- **SMOOTH** — прежняя точная полилинизация.

Критично: пересечения и момент топологического события находятся точно
всегда (`_EDGE_SAMPLES` и точность bisection не тронуты) — грубеет только
tessellation УЖЕ найденной кривой. preview форсирует HARD. Замер (резкий
угол 175°, ширина 0.4): SMOOTH 20 faces/64 верш → LOW 7/25 → HARD 5/19;
дискретизация LOW ширино-независима. Тесты `TestCurveProfile`. ROUND
junction cap тоже подчинён профилю (ROUND+SMOOTH — законсервированный
веер). Полный suite: `101 passed`.

## Follow-up 8: откат healing-подхода к общей границе (регрессия)

На стыке двух наезжающих лент одна сторона имеет miter с вершинами, а
соседняя — прямую хорду: силуэты расходятся, потому что кривую биссектрису
каждый сайт полилинизирует НЕЗАВИСИМО (свои crossings, свой обход).

Попытка `f038dd7` (откачена) содержала два изменения и сделала хуже:

1. Убрала ранний выход `_clip_polygon` по знакам вершин (сам по себе он
   неверен: кривая биссектриса может провиснуть через ребро, оставив оба
   конца внутри). Но однопроходный ассемблер контура не поддерживает
   получившуюся топологию: 4+ пересечения дают несколько компонент/линзу,
   которые сворачиваются в один самопересекающийся loop.
2. Добавила пост-проход `_heal_t_junctions`, вставляющий чужую вершину в
   ребро. Он чинит только коллинеарный T-junction (вершина уже на прямом
   ребре в пределах tolerance), а не расходящиеся кривые силуэты. Хуже —
   вставка ключа, уже присутствующего в face в другом месте (или в
   несколько рёбер), делает loop невалидным → `bmesh.faces.new` кидает
   `ValueError` → face исчезает молча. Отсюда наблюдение пользователя:
   во время drag (healing выключен) всё видно, после подтверждения
   (healing включён) часть геометрии у стыка пропадает.

Оба дефекта были на неправильном уровне. `f038dd7` откачен к `a410851`, а
`_materialize_network_faces` дополнительно перестал молча проглатывать
потери (повторы вершины убираются заранее, число drop печатается).

## Follow-up 9: planar arrangement общей границы (правильный уровень)

Взамен healing внедрён единый planar arrangement на 2D-полигонах ДО
lift/UV/materialize (ветка `codex/decal-shared-arrangement`, только
`decal_network.py`). Ключевые части:

- **`_shared_refined_chord`** — каноническая выборка одной zero-дуги:
  концы chord сортируются по ключу, поэтому обе стороны пары (обратный
  обход, обратный знак implicit) refine'ят участок в одном порядке →
  идентичные точки; per-pair `boundary_cache` переиспользует их. Так
  общая граница совпадает по построению, без T-стыка.
- **`_synchronize_pair_boundaries`** — вставляет общий набор zero-samples
  в обе стороны пары, но ТОЛЬКО в рёбра, оба конца которых лежат на
  pair-биссектрисе; чужие силуэты не трогаются.
- **`_normalize_surface_arrangement`** — завершает arrangement: режет рёбра
  во всех вершинах той же поверхности (degenerate multi-site случаи, где
  вершина третьего сайта попадает на pair-divider). Обе функции защищены
  `polygon_keys` — вершина, уже присутствующая в loop, не вставляется
  (именно этой защиты не было у healer'а → повтор → исчезновение).
- **`_split_repeated_polygon_loop`** — самокасающийся loop (multi-component
  из-за снятого early-out) раскладывается на валидные простые контуры, а
  не роняется.
- Все проходы гейтированы `not preview` — drag остаётся дёшев (preview
  пропускает arrangement), финал строит его.

Верифицировано оффлайн на репро-кейсах (без Blender): перпендикулярное
наложение и fold-угол со скрина — **0 T-стыков**, **0 повторов ключей**,
**0 mat-drops** (симуляция материализации), площадь без двойного покрытия;
101 существующий тест зелёный. Добавлен harness `TestArrangementValidity`:
`_assert_no_vanishing` (повтор ключа / нулевая площадь / mat-drop), T-стыки
и bowtie на screenshot-кейсах = 0, инвариантность к порядку сайтов.

Остаточно (записано честно): на плотных многосторонних junction'ах (3+
сайта в одной точке) остаются единичные bowtie/T-стыки — bmesh их создаёт
без ошибки (НЕ исчезают), это вопрос качества, не потери геометрии.
Финал ~2.6× дороже стабильного (sync+normalize O(pairs·points));
drag/preview не затронут. Скорость на больших сетях — отдельный слой
(static plan, width-independent cache, broadphase; см. `## Ограничения`).

## Follow-up 10: flat sweep broadphase candidate pairs

Полный поиск competitors выполнял для каждого site линейный просмотр всех
sites, хотя `_sites_compete` допускает только одну surface, а дальние bbox
заведомо не влияют. До клиппинга получалось O(S²). Новый
`_candidate_competitors`:

- группирует sites по `surface_id`;
- выбирает X/Y sweep axis по большему разбросу bbox-центров;
- держит плоский active-list и рассматривает каждую неупорядоченную пару
  один раз;
- сохраняет competitor order по `site_id`, поэтому последовательность
  half-plane clips и geometry output бит-в-бит совпадают с full scan.

На синтетической сетке из 2400 spatially-local sites candidate stage:
~2.30–2.41 s full scan → ~20 ms sweep (около 115×). На маленьком плотном
arc-comb общий preview меняется умеренно (~68 → ~63 ms), потому что там
почти все сайты локально близки и дальше доминирует clip kernel.
В Blender 4.3.2 тот же 2400-site benchmark: ~4.53 s → ~43 ms (около 105×).

Добавлены randomized differential (180 sites, 5 reach, 4 surfaces),
инвариантность к входному порядку, sparse-scaling на 1200 sites и exact
face/UV/vertex-key differential полного network build в preview/final.
Полный suite: `109 passed`; те же differential + arrangement проверки
пройдены внутри Blender 4.3.2.

## Follow-up 11: modal network compile plan

Manual SEAMS modal больше не повторяет width-independent анализ на каждом
движении мыши. `DecalNetworkPlan` один раз компилирует selected-edge runs,
branches, owner surfaces, conformal lift, site templates, junction sweeps и
station keys. Каждый кадр `evaluate_seam_network_plan` копирует только
изменяемое состояние ширины; обычные site bbox/segment caches также
переиспользуются. План хранится в экземпляре оператора и передаётся явно —
global mutable cache не появился.

One-shot `build_seam_network_faces` оставлен как совместимая обёртка
compile+evaluate. Differential-проверка подтверждает точный face/UV/key
паритет и изоляцию кадров в последовательности ширин A → B → A. Полный
suite: `111 passed`. В Blender 4.3.2 на маленьком плотном arc-comb median
preview снизился с ~63.70 до ~62.65 ms; выигрыш здесь ожидаемо небольшой,
поскольку основная оставшаяся стоимость — width-dependent clipping.

## Follow-up 12: exact spine-distance acceleration

Горячий `competition_distance_sq` больше не обязан линейно сканировать
длинный chain при каждом implicit-запросе. Sites от 40 сегментов получают
immutable 2D BVH с exact branch-and-bound nearest-segment query; короткие
sites сохраняют более дешёвый линейный цикл. Дополнительно canonical
implicit values одной site-пары кэшируются на время кадра и используются
обеими сторонами общей биссектрисы.

Оба ускорителя имеют независимые reference toggles. Differential для
preview/final сравнивает полный порядок faces, 3D positions, vertex keys и
UV с линейным ядром без кэша. Randomized point queries подтверждают exact
minimum длинного сайта. Полный suite: `114 passed`.

Blender 4.3.2, плотная синтетическая сеть: 64-сегментная дуга + 18
пересекающих ветвей, width 0.7. Финальный median preview: ~755 ms →
~441 ms (`1.71×`). Pair cache отдельно уменьшает число distance queries
примерно на треть. Blender exact oracle также материализовал ускоренный
результат в BMesh: `351 verts / 646 edges / 272 faces`.

## Follow-up 13: frame-local site distance cache

Последовательный clip одного polygon против нескольких competitors повторно
запрашивал расстояние от одинаковой 2D-точки до собственного и соседнего
site. Новый frame-local cache хранит точное метрическое расстояние по ключу
`site_id + point` и переиспользует его между разными site-парами. Кэш живёт
только внутри одного width evaluation: retraction следующего кадра не может
получить устаревшее значение.

Pair-value cache из предыдущего среза сохранён как независимый reference
toggle, но production его не складывает с site-cache: замеры показали, что
лишний pair lookup после общего site-cache немного замедляет и среднюю, и
плотную сеть. Exact differential отключает все три ускорителя одновременно;
отдельные call-count тесты закрепляют переиспользование между pairs.

Blender 4.3.2, тот же плотный benchmark: предыдущий production path
~441 ms → ~367 ms (`1.20×` за этот срез); относительно полного линейного
reference ~706 ms → ~367 ms (`1.92×`). На среднем arc-comb: ~91.9 ms →
~85.1 ms. Полный suite: `115 passed`.

## Follow-up 14: face-local clip bound + preview roots

Каждый исходный band-face теперь несёт строгую верхнюю границу расстояния
до owner spine. Для segment quad она считается до конкретного
spine-сегмента, для station fan — до центральной spine-вершины. Distance
до выпуклого segment/point — convex, поэтому максимум на вершинах face;
любой clipped component наследует тот же безопасный bound. Competitor,
чей spine bbox дальше bound, не может выиграть Voronoi comparison и не
вызывает `_clip_polygon`.

На modal preview crossing bisection останавливается при t-допуске `1e-6`
вместо финального `1e-12`. На проверенном плотном кейсе максимальная ошибка
3D-позиции ~`3.4e-7`, значительно ниже `DECAL_WELD_DISTANCE = 0.001`, а
после штатного final weld BMesh topology совпала (`344/633/272`). Confirm
rebuild (`preview=False`) всегда использует прежнюю точность `1e-12` и
бит-в-бит не изменён.

Blender 4.3.2: face-local gate убрал ~57% вызовов clip; вместе с preview
roots предыдущий path ~362 ms → ~272 ms (`1.33×` за срез, `2.59×` против
исходного линейного reference на том же benchmark). Полный suite:
`117 passed`.

Известный correctness follow-up: при экстремально широкой декали полностью
поглощённая same-surface сторона может не получить часть boundary samples
эталонной стороны. Это отдельная проблема symmetric arrangement после
исчезновения компоненты; оптимизационный срез её намеренно не маскирует.

## Follow-up 15: symmetric engulfed-boundary simplification

Экстремально широкий planar U/portal воспроизвёл визуальную асимметрию:
последовательный clip оставлял у одного угла короткий коллинеарный sliver
`source station → zero sample → divider`, тогда как зеркальный угол уже
схлопывался в station. При width `20` лишняя вершина находилась примерно в
`0.0093` от station — дальше final weld `0.001` — и оставалась отдельной.

После pair synchronization и surface normalization final arrangement
теперь выполняет глобальный degree-2 simplify. Sample удаляется сразу из
всех faces поверхности, только если у него ровно два уникальных соседа,
он строго лежит между ними на одной прямой и не является source station.
Поэтому dissolve не создаёт T-junction: реальные изгибы bisector,
junctions и structural stations сохраняются.

Regression на width `20` проверяет отсутствие unweldable near-station
samples, зеркальное равенство полного vertex multiset U-контура и отсутствие
vanishing faces. Modal preview не платит за этот проход; он выполняется
только для подтверждённой final arrangement. Полный suite: `118 passed`.

## Follow-up 16: arrangement tolerance соответствует shared keys

На production-сцене `testscene.blend` (148 selected seam edges, 218 sites,
21 owner surfaces) экстремальная ширина `8.6978` оставляла пять точных
T-разрывов в готовом BMesh. Диагностика до materialize нашла восемь
несинхронизированных попаданий vertex-on-edge; во всех случаях обе стороны
имели одинаковый `surface_id`, а численная дистанция составляла
`1.8e-7..8.9e-7`.

Причина — разные численные контракты одного arrangement: shared vertex keys
квантуются до 6 знаков, но геометрический split использовал допуск `1e-7`.
Численно эквивалентные точки могли попасть в соседние quantization cells и
не вставлялись в ребро соседней face. Final normalization и collinear
simplify теперь используют общий допуск `1e-6`, равный шагу key
quantization.

Повторный Blender 4.3.2 oracle на той же сети: `339` network faces,
финальный welded BMesh `514/954/338`, точных T-разрывов `0`. Одна
микроскопическая face размером меньше weld radius штатно схлопывается при
`remove_doubles`; это не потеря видимой области. Полный suite:
`119 passed`.

## Follow-up 17: shared planar partition для engulfed ribbons

Последовательный nonlinear clip оставлял независимые границы, когда очень
широкие half-cell полосы нескольких sites полностью поглощали друг друга на
одной owner-плоскости. Pair synchronization не мог исправить этот класс:
после исчезновения компоненты у одной стороны уже не было контура, из
которого можно зеркально перенести boundary samples.

Final evaluation теперь точечно включает общий planar arrangement только
для crowded surfaces (не меньше пяти sites), где одновременно обнаружены
нарушение owner constraints и proper X-пересечение. В общий segment graph
попадают source bands и результат legacy clip; sweep разбивает proper,
T- и collinear intersections, half-edge walk извлекает bounded atomic
cells, а каждая cell получает ровно одного ближайшего допустимого owner.
Corner folds, shared rails и простые специализированные 2–3-site miters не
перестраиваются. Modal preview также не затронут — partition выполняется
только после подтверждения drag.

Зависимость от Sverchok/pyvoronoi не добавлена: требуемый subset ограничен
уже существующими маловершинными polygon boundaries одной плоскости, поэтому
реализован локальный pure-Python segment arrangement. Общие координаты
канонизируются тем же six-digit key, который использует BMesh
materialization. Не конкурирующие spans одной ветви могут одновременно
считать cell допустимой, но физическая face создаётся ровно один раз;
неоднозначность разрешается минимальной дистанцией и стабильным `site_id`.

Blender 4.3.2 oracle, `E:\testscene.blend`, `walls.001`, 131 selected seam
edge, 198 sites, 17 surfaces:

- width `0.630592`: `746` network faces, `746` materialized, фактических
  X-пересечений после shared-key BMesh = `0`;
- width `8.0`: `1347` network faces, `1347` materialized, фактических
  X-пересечений = `0`;
- final weld сохраняет `0` пересечений; схлопываются только sliver-cells с
  минимальным ребром меньше `DECAL_WELD_DISTANCE = 0.001`.

Регрессия `dense_wide_partition_has_one_face_per_cell` воспроизводит полное
поглощение на ширине `8.0` и проверяет уникальность atomic faces и отсутствие
X-пересечений после shared-key materialization. Полный suite: `120 passed`.

## Ограничения

- Кривые поверхности группируются по планарным патчам
  (`DECAL_COPLANAR_DOT` + допуск по plane distance): на сильной кривизне
  сеть деградирует к посегментным сайтам с connector-стыками. Band
  unrolling вдоль chain — следующая фаза (потребует расширения
  analysis-контракта: face-strip вдоль chain).
- Кривые биссектрисы (точка-против-сегмента) полилинизируются с допуском
  sagitta = `DECAL_WELD_DISTANCE`; на прямых биссектрисах (все junction
  cases) хорды точны. Final arrangement вставляет общий набор T-samples в
  обе соседние стороны до lift/materialize.
- Кольцо со сменой поверхностей получает служебный разрез на wrap-станции
  (UV-шов там же, где у legacy).
