## 1. Цель и границы

Atlas решает случай, когда policy-free метрики показывают малое локальное
искажение ширины, но один глобальный hinge chart самоперекрывается внутри
materialization zone. Каноническая fixture — E.3 gentle saddle.

Atlas не ослабляет admission, не скрывает overlap и не создаёт новый modal
solve. Compile строит charts, transitions и equivalence classes; evaluate при
drag только применяет уже скомпилированное размещение и crops.

## 2. IR

`IntrinsicStripAtlas` содержит:

- упорядоченные `IntrinsicStripChart` с локальными метриками;
- `InteriorChartTransition` для каждой пары chart boundaries;
- canonical ownership source-triangle/source-region;
- общую station/V-phase систему;
- atlas-level aggregate metrics и admission tier.

`InteriorChartTransition` обязан хранить source edges, обе chart-side copies,
ориентацию, station interval и canonical `transition_key`. Ключ строится из
квантованных source/station facts по контракту D, а не из raw float modulo.

**R1 — Site images через transitions (обязательно).** Voronoi-диаграмма
каждого чарта обязана видеть конкурентов из соседних чартов: sites (и их
endpoint corners) в пределах `alpha_budget` от transition получают images
в соседнем чарте через изометрию перехода — тот же механизм, что
periodic copies D2 (images только в диаграмме, dedup при материализации,
счётчик `atlas_site_image_count`). Без этого фронты не сталкиваются
через переход и партиция чартов несовместна.

**R2 — Станции на transition вычисляются ровно один раз.** Любая
станция, лежащая на transition, вычисляется в owner-чарте и потребляется
соседом через equivalence class; пересчёт её позиции в соседнем чарте
запрещён. Обоснование: на non-developable поверхности перенос точки в
соседний чарт двумя путями расходится на holonomy (~defect * дистанция) —
если оба чарта считают одну станцию независимо, на переходе возникает
излом/щель. Канонический owner устраняет расхождение по построению;
остаточная ошибка внутренних границ вблизи перехода ограничена
E2-бюджетом ширины и отдельного допуска не требует.

**R5 — Единственный источник UV-frame'а (разрешение W1 stop по O1
raw-UV drift; R2-принцип, поднятый с 1D-станций на frames).**

1. Авторитеты разделены и НЕ взаимозаменяемы: transition owner
   владеет 1D-станциями (R2); UV-frame corner/segment site'а
   владеет его semantic owner chart — ровно один (единственность
   materialization owner, §4). «Transition owner» как источник UV
   не существует.
2. Imported frame — производная копия owner-frame'а: переносится
   изометрией transition-цепочки ВМЕСТЕ с V-phase offset. V-phase —
   1D компайл-факт цепочки (аккумулированная длина сети),
   path-independent по построению: потребитель НЕ пере-вычисляет V
   локально и НЕ выводит его из собственной геометрии.
3. R2-canonical election ранжирует по авторитету: локальный
   semantic-owner frame СТРОГО выше imported-копии; tie-break
   (chart_id) применим только между равноранговыми кандидатами.
   Равноранговые СУЩЕСТВУЮТ ровно в одном виде: обе стороны —
   imported-копии ОДНОГО И ТОГО ЖЕ owner-frame'а (owner — третий
   chart, не участник transition); такой tie легален только при
   same-owner provenance И согласии копий в tolerance — тогда
   chart_id детерминированно выбирает носителя. Два imported
   кандидата от РАЗНЫХ owner-frame'ов — НЕ tie, а upstream-дефект
   (T2-C coverage / R1 images), election его не разрешает. Подсчёт
   `authoritative_corner_uv == 0` у ОБОИХ кандидатов — дефект
   election, не основание для chart_id-tie. Provenance-ассерт:
   imported frame обязан трассироваться к своему owner chart;
   импорт из не-owner'а — дефект транспорта.
4. Выбор canonical сам по себе stop НЕ закрывает: O1 сверяет ОБА
   raw с canonical, значит drift обязан умереть в транспорте.
   Требование по построению: raw imported UV = owner raw UV ∘
   изометрия цепочки, расхождение <= tolerance. Обязательная
   диагностика до фикса — замер drift на обоих концах subedge:
   константный сдвиг вдоль станций = ошибка бухгалтерии V-phase
   offset в цепочке импорта (пропущенный либо задвоенный
   станционный offset или дуговой сегмент); растущий с дистанцией =
   ошибка изометрии/масштаба station mapping. Чинится транспорт;
   tolerance НЕ поднимается; формула V НЕ меняется.
5. Анти-тавтология O1: raw per-side = UV, вычисленный каждой
   стороной СВОИМ путём до R2-override — owner-сторона локальным
   frame'ом, consumer-сторона импортированным через транспортную
   цепочку. Независимость вычислительных путей + fault-injection
   (порча изометрии -> оракул обязан покраснеть) исключают
   тавтологию; сведение сравнения к «canonical против canonical»
   запрещено.

## 3. Декомпозиция

1. Стартовать с deterministic hinge placement C2.
2. Найти несмежные overlap pairs внутри `alpha_budget`.
3. Построить детерминированный separator по dual graph между overlap owners;
   tie-break — canonical source edge id.
4. Разрезать только chart topology. Source surface и итоговая геометрия полосы
   не разрезаются.
5. Повторять до локальной injectivity либо вернуть канонический reject reason.

**R3 — Детерминированная граница итераций.** Цикл сепараторов ограничен:
не более `min(8, support_triangle_count)` итераций; превышение — немедленный
`ATLAS_INJECTIVITY_UNRESOLVED`, не «ещё одна попытка». Ненулевой
`atlas_unresolved_overlap_count` после лимита — тот же отказ. E.N2 crumple
обязан проходить через atlas-путь до отказа за ограниченное время (negative
acceptance, см. §6).

Нельзя выбирать переход по текущей drag-ширине: topology atlas компилируется
на `alpha_budget`, поэтому S1 и `Construct() == 0` сохраняются.

## 3a. T-контракт: единое 1D-разбиение transition (поправка E4-ревью)

Предписанное решение блокера «два локальных arrangement дают
несовпадающие sliver-разбиения на transition». Ошибка предыдущей
попытки — порядок: два независимо разбитых 2D-графа сваривались
постфактум. Контракт инвертирует порядок: **сначала согласуется 1D
граница, затем каждый 2D arrangement строится уже конформным ей.**
Глобального 2D atlas-графа НЕ существует и не требуется (его нельзя
построить без глобального чарта — в этом весь смысл атласа);
atlas-wide объект — только 1D граф transitions.

**T1 — Каноническое пространство transition: 1D дуговой параметр.**
У каждого transition есть детерминированный owner-chart (по R2).
Каноническое пространство T — параметр длины дуги `t` вдоль
transition-polyline, квантованный на B0-решётке owner'а (целочисленная
1D решётка). Всё, что лежит на T, ключуется `(transition_id,
quantized_t)` — НИКОГДА 2D-координатами какого-либо чарта.

**T2 — Разбиение T вычисляется ровно один раз, owner'ом.**
T-station set = отсортированное объединение quantized t: (a) концы T;
(b) пересечения T с кривыми owner-чарта (в owner-пространстве);
(c) пересечения T с кривыми соседа: сосед ДЕКЛАРИРУЕТ свои
пересекающие кривые, отобразив их через изометрию перехода в
owner-пространство (машинерия R1 site images), owner считает параметры
пересечений в СВОЁМ пространстве; (d) R2 transition stations.
Готовый список раздаётся обоим чартам: каждый вставляет свою копию T
в локальный arrangement УЖЕ разбитой ровно в этих параметрах.
Локальным arrangement'ам ЗАПРЕЩЕНО дополнительно делить transition-
ребро. Если после отображения локальное пересечение не попадает в
канонический набор: в пределах одного кванта — снап к ближайшему
каноническому t; дальше кванта — жёсткий отказ
`ATLAS_TRANSITION_DESYNC`, не сварка. Overfull на transition-subedges
становится невозможен по построению: последовательность вершин на T
идентична с обеих сторон, каждый subedge имеет ровно одну грань с
каждой стороны.

**T3 — Кривые, пересекающие T, разрезаются НА T, не проецируются
СКВОЗЬ.** Ни одна 2D-кривая не существует в двух чартах как одна
сущность: кривая режется в каноническом t на две полукривые — часть в
A уходит в arrangement A, часть в B — в B; обе оканчиваются в общей
канонической вершине `(transition_id, t)`. Holonomy поглощается в
единственном легитимном месте: endpoint не-owner-полукривой ПЕРЕДВИГАЕТСЯ
в каноническую вершину (сдвиг ограничен E2-бюджетом) — это правка
конца кривой ДО построения arrangement, а не spatial post-weld граней.

**T4 — Грани остаются chart-local.** Face tracing — по-прежнему на
локальном arrangement каждого чарта, как в single-chart E4; обратной
«проекции traced faces» не существует, потому что грани никогда не
покидают свой чарт. Cross-chart смежность для manifold/M1-оракула
устанавливается через общие ключи subedge `(transition_id,
t-interval)` — они идентичны с обеих сторон по T2.

**T5 — Грань, «пересекающая» transition, невозможна по построению.**
Полная polyline T вставлена в оба локальных arrangement — T всегда
граница граней, никогда не внутренность. Классификация остаётся
per-chart с существующим приоритетом; transitions идут вдоль
source-рёбер, поэтому source-треугольник никогда не делится
transition'ом и владение материализацией однозначно.

**T6 — Sliver-политика на T.** Два declared-пересечения в пределах
одного кванта t детерминированно сливаются в одну каноническую
вершину (округление к решётке, слияние равных). Остаточный subedge
длиной в один квант легален и существует идентично с обеих сторон.

M1-оракул для атласа: overfull-подсчёт на transition-subedges ведётся
по каноническим `(transition_id, t-interval)` ключам — ровно 2 грани
на внутренний subedge (по одной с каждой стороны).

**T7 — Semantic transport (предписание по kind/UV-дефекту KITE↔SEGMENT).**
Диагноз: сосед не может и НЕ ДОЛЖЕН реконструировать corner-семантику
владельца — у него нет второго incident site (стратегия A добавляла
конкуренцию и ломала партицию 1->4; стратегия B давала предикат без
согласованных граничных кривых в графе и лишнюю материю 1->2; обе
верно откатаны). Принцип «владелец решает, сосед потребляет»
расширяется с геометрии на семантику:

1. Для каждой semantic-области владельца (corner component,
   junction-сектор), чья площадь пересекает T: владелец ОДИН раз
   отображает через изометрию перехода за-T-части её граничных кривых
   и передаёт соседу как **imported arrangement curves** — инертная
   геометрия (не Voronoi-сайты, не конкуренция, как рёбра
   domain-треугольников), заякоренная в канонических T-станциях и
   несущая ярлык владельца (kind, side, owner corner/site id, ссылка
   на UV-frame владельца). Import-набор compile-ограничен тем же
   радиусом alpha_budget, что R1.
2. Классификация соседних граней: грань, чья репрезентативная точка
   лежит внутри transported-области (ограниченной T-интервалом +
   imported curves — все они РЁБРА графа, потому рассинхрон
   предикат/грань невозможен), получает ярлык и UV-frame владельца
   (перенос — той же изометрией, что R2; holonomy в E2-бюджете).
   Вне области — обычная локальная классификация. Материя НЕ
   добавляется и НЕ вычитается — только переразметка уже
   существующих граней, теперь корректно ограниченных.
3. Ярлыки вычисляет владелец при каждом evaluation с текущими
   settings — threshold drag остаётся согласованным по построению
   (single source). Imported supporting-кривые статичны (S1),
   двигаются только frontier-части — compile topology
   ширино-независима.
4. Пост-трассировочная разрезка граней (вариант «separator от
   T-станции до ближайшей кривой») ЗАПРЕЩЕНА: multi-owner грань — это
   симптом ОТСУТСТВУЮЩЕЙ imported-кривой, а не задача для резака.
   С T7 разделители появляются в графе до трассировки.
5. Если transported-область пересекает более одной transition —
   механизм применяется по каждой, канонические вершины общего
   transition-графа общие; неоднозначность здесь = stop condition с
   минимальной фикстурой.

**T7-P — Примитив транспорта: открытые кривые, не замкнутые полигоны
(разрешение stop-condition T7.5, multi-owner face).**

Замкнутый crop-полигон как транспортный примитив порождает три
дефекта сразу: sliver'ы клиппинга, плавающие острова внутри граней
(требующие hole-support) и незаякоренные участки T, где 1D-ярлык
говорит «corner», а 2D-геометрия region'а до T не дотягивается —
именно это даёт SEGMENT-face, касающуюся двух corner-интервалов.
Предписание:

1. **Транспортируются ОТКРЫТЫЕ class-separating curves.** Для каждой
   станции смены класса эквивалентности вдоль T (смены ВНУТРИ класса
   — SEGMENT↔SEGMENT одной chain — сепаратора не требуют, O2)
   владелец находит у себя разделяющую кривую, инцидентную T в этой
   станции. Она обязана существовать: 1D-ярлыки суть сэмплы 2D-партиции
   владельца, смена ярлыка на T означает кривую владельца, пересекающую
   T в этой точке. Не нашлась в пределах кванта —
   `ATLAS_CLASS_DESYNC`, жёсткий стоп.
2. Владелец отображает **за-T-продолжение** этой кривой через
   изометрию перехода: опорная линия compile-статична (S1), extent
   ограничен reach области (`min(alpha_budget, собственный extent
   кривой)`). Открытая кривая, заякоренная в канонической станции,
   вставляется в граф соседа как инертная геометрия; snap-rounding
   режет её об остальные кривые ЕСТЕСТВЕННО — никакой отдельной
   логики «до первого пересечения» не пишется, это делает граф.
3. Остальные граничные кривые semantic-области экспортируются так же
   — открытыми, заякоренными либо в T-станции, либо в пересечении с
   другой imported-кривой той же области (цепочкой). Imported-кривая
   без связи с T или другой кривой графа ЗАПРЕЩЕНА — плавающие
   острова невозможны, hole-support в arrangement НЕ вводится.
4. **Классификация — отображением точки, не полигон-тестом.**
   Membership в transported-области проверяется так: репрезентативная
   точка грани соседа отображается изометрией В owner-chart и
   классифицируется ТАМ его собственными предикатами. Полигон-тест
   транспортированной области удаляется целиком. Грань ограничена
   образами кривых владельца, поэтому классификация внутри грани
   однородна; holonomy ограничена E2-бюджетом.
5. После п.1-2 нарушение O2 структурно невозможно: грань, касающаяся
   двух классов, требовала бы станции смены класса на своей T-границе
   без инцидентной кривой — а кривая там теперь есть по построению.
   Кейс касательной/коллинеарной T разделяющей кривой: смена класса
   лежит НА T, за-T-продолжения нет, O3 удовлетворяется самой T
   (инцидентна обоим графам по построению).

**T7-P2 — Аналитическое продолжение опорной кривой (разрешение stop
по multi-transition endpoint; уточняет T7-P.2).**

Диагноз кейса saddle (56,78), station 11: сепаратор владельца в
станции — arrangement-РЕБРО, т.е. СЛЕД опорной кривой на стороне
владельца. Ребро заканчивается там, где заканчивается, и его
«продолжение» изобрести нельзя — зеркалирование через T, ray в
interior и extension до support (все три проверенных варианта)
корректно провалились: это synthesized-геометрия, нарушающая
single-source. Транспортируется не ребро, а его ОПОРНАЯ КРИВАЯ.

1. **Сепаратор = граница пары предикатов, аналитически продолженная
   за T.** Владелец знает, какая пара областей (R1|R2) меняется в
   станции s. Их граница — аналитический объект из compile-фактов:
   ребро crop-полигона (прямая через две известные вершины кропа)
   либо bisector пары сайтов (site images R1 дают владельцу обе
   геометрии). Предикаты владельца — чистая геометрия и вычислимы за
   пределами его домена: владелец трассирует границу R1|R2 НА ДАЛЬНЕЙ
   стороне T в СВОИХ координатах и отображает изометрией в target.
   Это ровно та кривая, по которой T7-P.4 классификация (mapping
   представительной точки к владельцу) меняет ответ — поэтому после
   вставки грань не может охватить два класса ПО ПОСТРОЕНИЮ.
2. **Построение цепи** от станции s до первого из: (a) пересечение
   другой transition — якорь в ЕЁ канонической станции (T2-механизм
   той же transition; распространение по canonical transition graph
   вокруг общего endpoint — под-случай этой ветки, не отдельная
   конструкция); (b) triple point с границей третьего предиката той
   же области — общая вершина двух импортированных кривых (владелец
   считает всю цепь одним проходом и отображает одной изометрией —
   бит-точность внутренних вершин автоматична); (c) выход за reach
   области (`min(alpha_budget, frontier)`) — свободный конец, его
   обрезает snap-rounding об frontier/локальные кривые target'а.
3. **Ключевание non-T концов и extent'а**: T-якоря — канонические
   станции (T2); внутренние вершины цепи — квантованные вершины
   target-решётки из единственного owner-прохода (новый key-space не
   вводится); пересечения с target-локальными кривыми — обычный
   snap-rounding графа. Spatial weld и nearest-cut не существуют ни в
   одной ветке.
4. **Guard покрытия images**: если продолжение границы требует site
   image за пределами R1-радиуса — радиус images обязан покрывать
   reach области; нарушение = `ATLAS_CLASS_DESYNC` (stop), не
   эвристика.
5. Отклонено окончательно: транспорт owner half-edge polyline «как
   есть» (след обрывается на стороне владельца), зеркалирование,
   directional ray, synthesized nearest-cut.

**T7-P3 — Declared-owner классификация transition-касающихся граней
(разрешение stop по «unbounded boundary-owner fallback»; уточняет
§8b п.2, НЕ отменяя counted/bounded требование для slivers).**

Диагноз: буквальный 1-quantum gate ломает положительную
saddle-фикстуру, потому что прежний fallback смешивал ДВА разных
механизма под одной дистанционной эвристикой. Face, касающийся
canonical transition, уже получает от T2-декларации стороны множество
interval-owner токенов (`side.interval_owners` по накрытым
станционным интервалам). Дистанция до локального crop-образа
владельца (669q в репро) в семантике не участвует: локальный образ
материи владельца может лежать сколь угодно далеко, метка от этого
не меняется.

1. **Расстояние никогда не является источником метки.** Метка face —
   функция T2-декларации и owner-space предикатов. Локальный
   nearest-crop кандидат используется ТОЛЬКО как носитель атрибутов
   (site-геометрия); kind/side/edge_index определяются declared
   токеном и interval_semantics, crop-геометрия носителя в решении
   не участвует. Носитель разрешён на любой дистанции; при полном
   отсутствии локального носителя токена — диагностический стоп
   `ATLAS_TRANSITION_DESYNC` (counted), не импровизация атрибутов.
2. **|declared tokens| == 1 — семантическое присвоение на любой
   дистанции.** Face, чей transition-span накрывает интервалы
   единственного владельца E, получает метку E безусловно. Это НЕ
   adoption и НЕ spatial weld: декларация T2 и есть
   транспортированный owner-space SEGMENT-предикат в интервальной
   форме (1D-сэмплы партиции владельца, T7-P.4). Новый счётчик
   `atlas_declared_owner_count` (отличен от sliver-счётчика).
   Обязательная сверка: при объявленном `expected_semantic_class`
   класс присвоения обязан совпасть — расхождение =
   `ATLAS_TRANSITION_DESYNC`, не тихое принятие.
3. **|declared tokens| >= 2 — tie-break ТОЛЬКО owner-space
   предикатом.** Разные классы эквивалентности в declared-наборе
   (ПОСЛЕ канонизации п.7) — структурный провал O2 (отсутствует
   imported-кривая; чинится T7, не тайбрейком). Один класс
   (SEGMENT-цепочка) — выбор токена детерминирован интервалом:
   representative отображается изометрией transition в owner-chart,
   его проекция на T-ось классифицируется ТОЧНЫМ half-open
   containment — интервал `[s_i, s_{i+1})` в станционных
   координатах, последний интервал замкнут справа. Никакого «стопа
   по близости к станции»: face, легально накрывающий несколько
   интервалов ОДНОГО класса (O2), штатно даёт representative у
   внутренней станции (0.434q в положительной saddle-фикстуре,
   chart 15, width 0.25). Проверка «face обязан был быть разрезан»
   принадлежит O2 на class-change станциях, не proximity-эвристике
   tie-break'а. Выбор внутри одного класса эквивалентности —
   атрибутивный, не семантический: любой детерминированный ответ
   корректен, half-open — канонический; U/V-непрерывность
   гарантируется T8/O1. Локальная дистанция как tie-break
   запрещена по-прежнему.

   **3a. Тотализация проекции (clamp).** У большого face боковая
   проекция representative на ось transition может лечь ВНЕ его
   собственного touched-span'а (репро: station 667.66 при declared
   `[1871,1993]`; 473.64 при `[0,8]`) — это артефакт латеральной
   геометрии, не признак чужого авторитета. Перед half-open
   containment проекция клампится в touched station span этого face
   на этой transition (спан контакта — и есть домен декларации T2
   над этим face). Кламп 1D, входы — квантованные станции,
   детерминизм полный; при проекции внутри спана — тождество
   (обратная совместимость с прежним правилом).

   **3b. Multi-transition атрибутивное разрешение.** Face, касающийся
   НЕСКОЛЬКИХ transitions с объединённым declared-набором одного
   класса эквивалентности: кандидат каждой transition разрешается
   по 3a независимо; итоговый токен — кандидат transition с
   МАКСИМАЛЬНОЙ мерой touched-span'а в станциях (максимум контакта
   = минимум экстраполяции frame'а владельца); равенство мер —
   канонический порядок (canonical transition key, старт интервала,
   токен — все целые). Обход transition graph для атрибутивного
   выбора НЕ ТРЕБУЕТСЯ И НЕ РАЗРЕШЁН: он возвращал бы
   геометрию-решает-семантику и неограниченную механику для
   решения, которое внутри класса семантически свободно (T8/O1
   гарантируют непрерывность при любом детерминированном выборе).
   Репро chart 16: (15,36) даёт 12030 при спане ~122 станции,
   (15,37) даёт 12028 при спане ~8 → атрибуция 12030.
4. **Multi-hop** — ТОЛЬКО для owner-space оценки предикатов
   КЛАССОВОГО уровня: триггер — отображённая изометрией точка лежит
   за следующей canonical transition в owner-space; тогда авторитет
   уходит дальше по цепочке T7-P2.2(a); итерация ограничена R3
   (`min(8, support_count)`), превышение =
   `ATLAS_TRANSITION_DESYNC`. Проекция вне touched-span'а multi-hop
   НЕ запускает (это кейс 3a); атрибутивный выбор токена multi-hop
   не использует никогда (3b).
5. **B0-sliver правило БЕЗ декларации не меняется**: строго <= 1
   квант + `atlas_sliver_owner_count` (§8a/§8b). Дальше кванта без
   декларации — drop с существующими counted reasons
   (`atlas_touch_no_token_drop_count` и родственные).
6. Отклонено: слепой beyond-quantum spatial adoption (маскирует
   misclassification); drop декларированных faces (ломает связность
   band'а — репро `[646, 5, 2]`: эти faces load-bearing по
   построению); ослабление component/double-cover оракулов;
   транспорт новых SEGMENT-кривых через T7-P2-механику (избыточен —
   интервальная декларация T2 уже несёт предикат).
7. **Канонизация вырожденных интервалов T2** (владелец, один раз,
   ДО вычисления class-change станций и separator-требований).
   Интервальная семантика, сэмплированная на суб-квантовой
   геометрии, недостоверна по построению — вся T-механика
   квантуется решёткой. Репро: near-boundary ветка выборов
   владельца интервала (`_m1_build_transition_contract`,
   `boundary_distance <= 1.5 * quantum` понижает класс до SEGMENT)
   выдаёт хвостовой интервал длиной ровно 1 квант с иным
   токеном/классом — фантомная смена класса, требующая фантомного
   сепаратора при пустых `semantic_imports`. Правило: интервал
   длиной <= 1 кванта поглощается соседним ДО публикации контракта
   потребителям: единственный сосед (конец transition) — им; два
   соседа — соседом того же класса эквивалентности; оба соседа
   иного класса — `ATLAS_TRANSITION_DESYNC` (две смены класса
   внутри кванта неразрешимы на решётке). Инвариант публикуемого
   контракта: ни одного интервала длиной <= 1 кванта. Счётчик
   `atlas_degenerate_interval_merge_count`. Разрешённый
   имплементационный эквивалент — снап станции в границу transition
   в той же normalization-ветке, при сохранении инварианта и
   счётчика. Это T6-принцип (sliver merge) на 1D-уровне контракта,
   а НЕ ослабление O2: O2 остаётся строгим на канонизированном
   контракте.
8. **V-континуация через same-chain corner ниже разрешения решётки**
   (разрешение W1 stop chart4, transition (5,26); atlas-проекция
   SMOOTH sub-band из bands-оракула `decal_corner_bands.md`).
   Феномен ОДИН на трёх слоях: у почти-прямого угла (репро corner5:
   interior 3.14200 rad, tau ~ 0.0006 rad) ширина corner-клина
   ~alpha*tau — порядка кванта, поэтому (1D) его интервал поглощён
   канонизацией п.7, (2D) его crop-структура схлопнута
   snap-rounding'ом и большой face ЛЕГАЛЬНО пересекает
   endpoint-frame, следовательно (UV) формула V обязана течь сквозь
   угол. Правило: `_site_v_length` НЕ clamp'ит параметр на
   same-chain shared endpoint — арк-длина цепочки продолжается
   аналитически (линейное продолжение параметризации сегмента;
   входы — компайл-факты: смежность цепочки и V-offset соседа;
   width-независимо, S1-safe). **Гейт континуации — структурный
   предикат, НЕ коэффициент** (уточнение после stop chart14:
   alpha*tau = 1.55q при буквальном пороге 1.5q — любой фиксированный
   коэффициент гонится за исходом квантования вместо чтения самого
   исхода). Компайл записывает факт исхода собственной crop-сборки:
   `corner_structure_absorbed(corner)` = True, когда crop-структура
   угла при квантовании/snap-rounding выродилась (суб-квантовая /
   нулевая площадь) и НЕ эмитирована во входы arrangement.
   Континуация разрешена <=> same-chain сосед и corner
   присутствуют в диаграмме (R1 полон) И absorbed == True — при
   ЛЮБОЙ величине overrun. absorbed == False при overrun — hard
   fail (реальный дефект: face обязан был быть разрезан кривыми
   угла); отсутствие site/image соседа — hard fail (R1);
   absorbed == False, но кривых угла в arrangement нет — дефект
   пайплайна (кривые потеряны после compile), fail. Числовые
   пороги в предикате запрещены; формула «tau <= ~q/alpha»
   первоначальной редакции — оценка масштаба, не предикат.
   Корректность без коэффициента: ошибка континуации ~alpha*tau =
   ширина невыжившего клина, по факту absorbed — квантового
   порядка, и с большим запасом внутри O1-допуска
   `max(1.5q, 2% alpha)` (репро chart14: overrun 2.01q при допуске
   2% * 0.125 = 25q). Счётчик `atlas_v_continuation_count`;
   применимо и к внутренним faces без transition (авторитет гейта —
   компайл-флаг, не контракт; поглощение интервала T7-P3.7 — лишь
   1D-тень того же факта на transition). Clamp на
   СВОБОДНОМ конце цепочки (без same-chain соседа) остаётся
   дефектом (CAP-зона/пропавший конкурент). Глобальный guard
   `atlas_clamped_segment_face_count == 0` НЕ ослабляется и не
   переформулируется — устраняется ПРИЧИНА ложного класса
   срабатываний, не проверка. Полный SMOOTH sub-band (crop-side
   pass-through) — вне W1, остаётся C8.3 stable-пути; здесь только
   evaluate-формула V. Поправка предпосылки п.3/3b: «любой
   детерминированный токен внутри класса корректен» верно ТОЛЬКО
   при chain-непрерывной V-формуле — именно её восстанавливает
   это правило; imported-копии frame'ов переносят закон континуации
   вместе с frame'ом (R5.2 без изменений).
9. **Enforcement-порядок separator-требований** (разрешение W1 stop
   chart5, transition (5,27): смена класса SEGMENT 12010 -> KITE
   12012 в станции 2831, kite с lattice interior, face не
   разрезан). Это НЕ новая механика — это обязательность T7-P.1,
   поднятая в явную стадию пайплайна. Requirement-стадия: из
   КАНОНИЗИРОВАННОГО контракта (после поглощений T7-P3.7) для
   КАЖДОЙ станции смены класса эквивалентности владелец обязан
   найти и экспортировать разделяющую кривую (T7-P2.1: опорная
   линия — компайл-факт, здесь ребро kite crop-полигона между
   ячейками 12010 и corner6), заякоренную в канонической станции
   (T2-ключ, T3 endpoint-перенос, вставка inert geometry,
   snap-rounding режет — механизмы существующие, новых нет). Не
   нашлась в пределах кванта — `ATLAS_CLASS_DESYNC` НЕМЕДЛЕННО,
   ДО arrangement. Тихий пропуск требования запрещён: O2/T8 —
   backstop-оракул, не первичный детектор; ошибка, впервые
   видимая на O2, — дефект requirement-стадии. Негатив T7-P3.8
   «absorbed=False и кривых нет в arrangement» при работающем
   enforcement недостижим — остаётся страховкой пайплайна.
   Отклонено: (A) определять absorbed по отсутствию materialized
   corner face после tracing — цикл contract<->arrangement и
   неотличимость от негатива «потерянные кривые»; флаг остаётся
   компайл-фактом исхода crop-квантования (Pick I == 0 —
   корректная реализация); (B) канонизация span <= 2 —
   коэффициент, плюс уничтожение РЕАЛЬНОЙ семантики
   резолвабельного kite, а не поглощение суб-резолюционного шума.
   После фикса face режется в 2831 (и в следующей class-change
   станции при касании), узкая kite-полоса — обычный T6-кандидат;
   O2 удовлетворён по построению (T7-P.5).
10. **Честные декларации и авторитет принадлежности** (разрешение
    W1 stop width=0.5; три под-решения).

    **10a. Удаление fuzzy-переименования — ОБЯЗАТЕЛЬНО** (вариант A
    исполнителя верен; ветка `midpoint <= 1.5q -> SEGMENT` в

    переписывание ярлыка дистанционной полосой без кривой в графе

    фикстурой с честным 1q-интервалом.

    **10b. Класс-детекция token-blind; предикатный гейт requirement
    НЕ вводится** (вариант B). Смена класса = смена T8-класса
    эквивалентности между соседними интервалами НЕЗАВИСИМО от
    совпадения owner-token: SEGMENT и KITE с одним token — разные
    классы всегда (репро chart8: token 12016 на обеих сторонах —
    сепаратор обязателен). Requirement-поиск (T7-P3.9) сам и есть
    подтверждение предиката: кривая нашлась в пределах кванта —
    ok; не нашлась — `ATLAS_CLASS_DESYNC`, и station499 — образец
    ценности этого стопа: он вскрыл ложь контракта из 10a.
    Пре-фильтрация требований «подтверждённым пересечением» — тот
    же поиск, выполненный дважды.

    **10c. Авторитет принадлежности — кривые arrangement, НЕ
    endpoint-перпендикуляр** (вариант C). Перпендикуляр в endpoint
    — граница домена ПАРАМЕТРИЗАЦИИ (проекции на сегмент), он не
    является кривой графа и не определяет принадлежность; face
    принадлежит тому, чем ограничен (single-cover). Числовая улика
    репро: overrun 3.34q ~ alpha*tau = 0.25*0.00124 = 3.1q —
    ширина наклонного sliver'а между перпендикуляром и реальной
    разделяющей кривой почти-прямого угла (+ snap-jitter < 1q).
    ОБЯЗАТЕЛЬНЫЙ диагноз-шаг до кода: содержит ли граница
    overrun-face материализованную разделяющую кривую corner14?
    - ДА -> третья ветвь гейта T7-P3.8: континуация разрешена

      материализованной corner-структурой (сепаратор входит в
      границу face). Остаточный overrun — наклонный sliver,
      само-ограниченный той же кривой (~alpha*sin(tau)); ошибка
      континуации того же порядка (репро: 3.1q при O1-допуске
      2%*alpha = 50q). Предикат структурный — «кривая в границе
      face», чисел нет.
    - НЕТ -> честный дефект импорта сепаратора на КОНЦЕ transition
      (station1 = конец (35,57)): якорение по T7-P2.2(a) —
      canonical transition graph вокруг общего endpoint, экспорт
      через смежную transition; чинится requirement-стадия

      механизмы не изобретаются.
    Примечание: alpha-зависимость absorbed-флага (vertex14:
    absorbed при alpha=0.125, не-absorbed при 0.25) — по
    построению: флаг — факт исхода crop-квантования данного
    compile, не свойство угла.

**T2-C — Coverage-инвариант T2-декларации (разрешение W1 stop

Ярлыки интервалов группируются в классы семантической
эквивалентности: corner-kinds эквивалентны при равных
(kind, owner corner id); SEGMENT-ярлыки эквивалентны при одной chain
и V-непрерывности в общей станции (в пределах кванта). Оракул:

- O1: для каждого внутреннего transition-subedge обе смежные грани —
  в одном классе эквивалентности; U (как u*alpha) и V в обеих общих
  станциях совпадают в пределах кванта.

  ярлыки в одном классе (SEGMENT 12016 + SEGMENT 12018 одной chain с
  непрерывной V — легально; KITE + SEGMENT — структурный провал =
  отсутствует imported-кривая; чинится T7, не переразметкой).

  в которой в ОБОИХ локальных графах инцидентна разделяющая кривая
  (локальная или imported).

## 4. Materialization и сварка

- Каждый source-region имеет ровно одного materialization owner.
- Соседний chart может иметь overlap margin для вычисления, но не создаёт
  вторую геометрию в owned region.
- Совпадающие boundary samples свариваются только по transition equivalence
  key; координаты одной equivalence class берутся из канонического owner.
- V наследуется от общей network station; U согласуется ориентацией transition.
- На transition запрещены щель, double cover, flipped winding и UV phase jump.

## 5. Admission и диагностика

Каждый chart проходит локальные G1/G3/G4/G5/G6/G8 и organic width/normal gates.
G2 применяется к materialized atlas arrangement: overlap рабочих chart margins
не является ошибкой, double materialization является.

**R4 — Категории cuts не смешиваются.** Atlas-сепараторы — отдельная
категория (`ChartCut.reason = ATLAS_SEPARATOR`) и НЕ считаются в
single-cut правиле G7: G7 ограничивает только periodic/boundary
generating cuts. Сепаратор обязан соблюдать EP4-исключение осознанно:
он ПРОХОДИТ через materialization zone (в этом смысл E3), но материю не
режет — шов существует только в chart topology и сваривается
transition-ключами до эмиссии.

Обязательные counters:

- `atlas_chart_count`;
- `interior_transition_count`;
- `interior_weld_count`;
- `atlas_unresolved_overlap_count`;
- per-chart width error / normal variation / foldover.

Новый отказ: `ATLAS_INJECTIVITY_UNRESOLVED`. Он не маршрутизируется как
APPROXIMATE и не маскируется legacy-геометрией внутри успешно принятой части.

## 6. Acceptance

1. E.3 gentle saddle: ноль unresolved materialization overlap, cracks,
   double cover, foldover и UV phase jumps.
2. `max_width_error_sampled <= decal_chart_distortion_budget` после stitching.
3. Transition geometry бит-точна при reversed enumeration и повторном compile.
4. Width drag не меняет chart topology/supporting lines; `Construct() == 0`.
5. C7, D4 и walls differential при дефолтах байт-идентичны.
6. E.1 sphere S1 остаётся зелёным.
7. Negative: E.N2 crumple через atlas-путь -> `ATLAS_INJECTIVITY_UNRESOLVED`
   за ограниченное число итераций (R3), без частичной геометрии.
8. Фронт-коллизия через transition: фикстура с двумя цепочками в разных
   чартах atlas'а — фронты сталкиваются корректно (site images R1),
   шов коллизии S1-стабилен при drag.

## 7. Stop и разрешённые fallback decisions

Остановиться до production merge, если E.3 требует изменения B0 quantization,
double materialization или width-dependent topology. Приложить метрики и
минимальную fixture к одному из двух явных решений:

- временно перевести saddle в REJECT/deferred;
- открыть отдельный conformal research spike.

Conformal spike обязан отдельно ответить на headless execution parity,
dependency policy, determinism, compile/evaluate split и differential. Сам факт
лучшей картинки не является разрешением включить его в production.

## 8. Независимое review до implementation

Ревьюер должен проверить:

1. что atlas не превращает chart/corner в новую runtime placement unit;
2. однозначность ownership и отсутствие double cover;
3. достаточность transition key для бит-точной сварки и UV parity;
4. отсутствие width-dependent compile topology;
5. корректность G2 на atlas arrangement;
6. достижимость E.3 без скрытого conformal solve;
7. полноту negative tests и canonical reject path.

После review статус меняется на **APPROVED** с commit/reviewer evidence.
