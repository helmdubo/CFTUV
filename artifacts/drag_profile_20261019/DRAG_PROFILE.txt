2. WIDTH DEPENDENCE OF THE STAGES (what a tick recomputes)
   - EXPORT, PLAN_COMPILE, DOMAIN_BUILD, ARRIVAL, BRIDGE, SKELETON, FACES: width-independent and ALREADY NOT RECOMPUTED. Proof by execution count: 0 of
     2 x 7 x 122 + 2 x 6 x 1053 task records on lean/commit refreshes ran task_inputs or prepare_for_production (dragprof_runner worker laps); the content key
     excludes alpha (envelope_content_key.EXCLUDED_FIELDS) and the worker store key is the hash of the preparation bytes. Exception (not hit in these ranges,
     up to +10.5 % building / +9 % cover): a tightened band chart whose reach alpha*(1+b) changes evicts the domain's preparation (envelope_debug_session._note_band_chart).
   - PRODUCE (coverage + materialize) is the whole worker cost of a tick. Inside a domain's certified interval its outputs were compared at 3 + 3 widths:
       structure signature (vertex keys, face rings = tessellation/fans/caps, chains = seams/interfaces, station facts, regions, diagnostics):
         building 846/846 samples IDENTICAL, cover 3656/3657 IDENTICAL (1 change, see 4);
       exact slopes (map points, lifted positions, (s, r) UV facts): equal at every inside width (theorem 0 failures, 846 + 3656 judged);
       binary64 slopes (bytes): equal in 844/846 and 3656/3656 (the 2 building cases differ in float order only; the exact slopes are equal).
     So inside an interval the TOPOLOGY decisions (SILHOUETTE, tessellation, ASSEMBLE chains, regions) and the PARAMETRIC slopes give the same output at
     every width, and positions/UV are an exact affine function of width. Width-independent recompute in a lean tick:
       strictly identical output: PARAMETRIC 0.176 / 1.277 worker-s (about 0.012 s / 0.11 s of wall at 12 workers);
       structure-determined + exactly affine: all of PRODUCE.materialize + coverage, 1.34 / 9.10 worker-s = the pool part of the tick
       (0.15 s / 1.0 s wall) - this is what WIDTH_REFRESH_INCREMENTAL_V1 already skips (incr tick 0.057 / 0.041 s), WITHOUT certifying the structure;
       parent bookkeeping that does not depend on alpha: scan (request rebuilt per patch, memo hits) 0.014 / 0.112 s, order_by_cost 0.003 / 0.025 s.
   - CACHE POTENTIAL (seconds of the exact lean tick): building 0.212 -> ~0.05 (-0.16 s), cover 1.44 -> ~0.06-0.15 (-1.3 s) if the structure inside the
     interval is certified (plan A below); without certifying it, -0.012 / -0.24 s (PARAMETRIC memo + scan) (plan B).
