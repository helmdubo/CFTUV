1. МОЙ ВЫБОР

Нужен кэш сертифицированных интервалов ШИРИНЫ, очередь ближайших событий и
переиспользование структуры меша. Ширина здесь — один параметр. На кадре без
события меняются массивы координат и UV; на событии пересчитывается затронутый
PatchDomain и зависимые от него операции хоста. Единица ядра остаётся
(DecalRequestId, PatchDomainId) со всеми источниками вместе.

Сравнение вариантов:
- Octree/Sparse Octree: полезно для поиска геометрии в пространстве, но изменение
  общей ширины двигает границы многих удалённых друг от друга доменов. Близость
  в XYZ не определяет близость к следующему переключению UV-fit/тесселяции.
  По профилю preparation уже не повторяется; 8.167 из 9.912 worker-seconds lean
  cover008 приходится на materialize. Дерево поиска эту работу не отменяет.
- 2D grid/BVH по chart-примитивам: вспомогательный broad phase для построения
  кандидатов пересечений. _Grid уже есть в K/interval.py:198-219. Менять индекс
  имеет смысл после измерения именно его стоимости. Ложные кандидаты допустимы,
  потерянные — нет. Вне этого расчёт должен оставаться тем же.
- Таблица равномерно выбранных ширин: быстрее на cache hit, но не доказывает
  отсутствие события между образцами. Два близких образца могут иметь одну
  структуру, а между ними лежать другое состояние. Не подходит как exact-law.
- Rust-перенос полного materialize: полезный независимый путь для miss/fallback,
  но повторяет геометрический выбор на каждом кадре.
- Выбранный путь: маленькое число локальных интервалов на домен, точные законы
  движения, очередь окончаний интервалов, фоновая подготовка ближайшего соседа.
  Это применение kinetic certificates к ширине, а не к времени.

Главный выигрыш: убрать повторный геометрический ВЫБОР. Стоимость записи V вершин
и L UV-петель остаётся O(V+L). Нельзя обещать 60 fps по одному профилю ядра:
на cover008 уже измерена запись lean frame ~19 мс, _apply ~31 мс; обновление GUI
и его triangulation/draw cache headless-прогон не измеряет. 50–150 мс exact tick
из прежнего профиля — гипотеза ускорения, не realtime 60 fps и не новый замер.

2. УТОЧНЕНИЯ, БЕЗ КОТОРЫХ ДИЗАЙН НЕ ГОТОВ К РЕАЛИЗАЦИИ

2.1. Не все UV аффинны по ширине.
K/parametric.py:5-16,127-154; K/uv_law.py:45-57:
  X(w) = X0 + X1*(w-w0)
  S(w) = S0 + S1*(w-w0), R(w) = R0 + R1*(w-w0)
  UV(w) = (S(w),R(w))/(scale*w).
Для участка с иным effective-alpha law сохраняется именно его знаменатель,
а событие смены active/frozen режима ограничивает интервал. В host-certificate
наклон UV означает наклон произведения UV*w. Линейно интерполировать сам UV нельзя.

2.2. Нет общего обещания «все корни рациональны или Q(sqrt(q))».
Точки и факты используют SqrtSum, то есть несколько радикалов. Даже квадратное
уравнение над таким полем может потребовать расширения. UV-fit порождает более
высокую степень. Нужны полином + точное поле коэффициентов + изолирующий
рациональный интервал; либо доказанное отсутствие корня на рабочем окне.
Бисекция по смене знака НЕ находит касание/чётный корень и два корня между
одинаковыми знаками. Использовать root count/isolation (Sturm/Descartes с
поддержанным полем) или sound interval/Bernstein proof; unresolved => отказ.

2.3. Точная математика и текущая floating-point семантика — разные обязательства.
Событие корня в точной формуле не заменяет решение binary64-кода. Результат
настоящего UV-fit ниже осциллирует в окрестности корня. Нужен доказанный
FP_UNCERTAINTY_BAND, внутри которого работает существующий full path.
Выбор фиксированного epsilon по нескольким образцам не является доказательством.
Должны учитываться centre_and_bound, enclosure(64), нормализация, determinant,
деления, max/abs, hypot, atan2 и конечность значений. Ошибка enclosure масштабируется
коэффициентами и обусловленностью, а не универсальным относительным 2^-64.

2.4. Бюджет — часть поведения, а не только телеметрия.
K/silhouette.py:843-862 может вернуть исходную сетку при SKIPPED_WORK_BUDGET;
K/domain.py:1121-1129 может отказать. Условие «на w0 потрачено меньше половины
бюджета» не доказывает результат на другой ширине. K/step.py:262-286 сравнивает
счётчики и цену покрытия. PRICE_AT_RECORD_WIDTH не эквивалентен текущему контракту.
Для strict exact нужен доказанный replay/upper bound на admitted input set;
без него LAZY_BUDGET_UNPROVEN и full. Более слабый контракт только геометрического
кадра можно согласовать отдельно, но он не называется full-answer-identical.

2.5. Сертификат только итоговых вершин недостаточен.
K/parametric.py:606-637 обходит surviving batch.vertices; удалённый кандидат
всё равно нужен для доказательства, что он останется удалённым. Tape должен
удерживать законы ВСЕХ прочитанных операндов: до/после clip, до silhouette,
неудачных merge, точек проверки shortcut, station conflict и отказов.
Две/три точные выборки полезны как проверка; допуск lazy требует доказанного
вида функции, denominator guards и неизменности её support, не подгонки.

2.6. Кэш ядра не сертифицирует сваренный меш хоста.
H/envelope_production_weld.py:210-244,292-398,650-660 выбирает классы сварки,
партнёров стен, митры и UV-швы; там есть побитовое равенство float-позиций,
порог направления и ограничения митры. Нужен отдельный host-assembly certificate
на группу зависимых доменов или пересчёт этих функций на каждом exact кадре.

3. АУДИТ РЕШЕНИЙ И ФОРМУЛ ПЕРЕКЛЮЧЕНИЯ

Нынешний K/interval.py:56-64,296-343 ограничивает arrivals и source-line/source-vertex
clip crossings, включая snap bands, но оставляет пять UNCERTIFIED-классов.
Ниже разложены эти классы и дополнительные решения. Это аудит семейств условий,
не уже реализованное доказательство полноты trace. Перед допуском нужен manifest
всех исполняемых сайтов с classification: EVENT / STATIC / PROVED_FILTER / REFUSE.

В формулах p=a+b*w; все коэффициенты берутся из preparation + конструкции
coverage/clip + trace материализации текущей ветви. Preparation уже достаточна
как исходный набор данных, но готового tape для этих решений сейчас нет.
K=Q(sqrt(q1),...,sqrt(qm)). «Точно» далее означает алгебраический корень над K,
а не обязательную представимость единственным sqrt. Для float-сайтов нужна
оболочка результата исполняемой процедуры; реальный полином — только её опора.

E01 COINCIDENCE / SOURCE_ID / ZERO_EDGE.
  K/coalesce.py:400-417,454-457,483-486,513-546; K/mesh.py:157-188;
  K/chord_station.py:209-257. Совпадение точек, появление source-имени,
  нулевое ребро, adjacency компонентов и конфликт ключа.
  Решить a_i+b_i*w=0 одновременно по координатам; w=-a_i/b_i,
  проверить остальные равенства. Для source identity сравнивать с конечным
  набором table.node_vertex_ids, а не перечислять всю целочисленную решётку.
  Тождество на всём окне => STATIC; совпадение лишь в одной точке => AT_EVENT.

E02 ORIENTATION / AREA / SEGMENT_ORDER.
  K/tessellate.py:58-193,237; K/coalesce.py:320-325,588;
  K/clip.py:776-795,939-985,1085,1124-1141;
  K/silhouette.py:305-312,415-430,700-753.

E03 TESSELLATION / W1 PARTITION / CONVEX MERGE.
  K/mesh.py:577-613,675-695,774-856,881-913;
  K/convex_partition.py:104-218,249-270;
  N/cftuv-mesh/src/{tessellate.rs,partition.rs,predicates.rs,affine.rs,mesh.rs}.

E04 AFFINE_UV_IDENTITY.
  K/tessellate.py:253-309; K/mesh.py:791-816;
  K/silhouette.py:299-302,415-430,511-528.
  D=det(p1-p0,p2-p0); N1,N2 — числители barycentric координат q.
  D*(f_q-f0)-N1*(f1-f0)-N2*(f2-f0)=0 для каждой station-компоненты;
  степень <=3 при аффинных фактах. Смена опорной тройки: D=0 (E02).
  У clip-факта более сложный рациональный закон => очистить знаменатели с
  записью их нулей или LAZY_OPERAND_NON_AFFINE, не объявлять cubic автоматически.

E05 CAP / FAN / RUNG / STATION_WITHDRAW.
  K/mesh.py:213-221,239-259,257-289,340-364,616-667,934-959;
  K/domain.py:957-983; K/clip.py:1619-1637; K/frames.py:142-199.
  Наличие apex: p(w)=owner; star fan/ears: E02; station/join identities:
  r_a-r_b=0, s_a+s_b-2*s_join=0; denominator/axis выбора chord и share=0/1.
  Для chord share=(p_axis-u_axis)/(v_axis-u_axis): нули числителей, знаменателя

  Конфликт фактов может снять junction и перестроить station table, поэтому

  terminal compile-static при неизменной preparation; их появление в покрытии

E07 HOST_SOURCE_REBIND / FOLLOWER / ORIENTATION_REPAIR.
  K/source_lift.py:260-270,283-299,351-390,449-489.

E08 SILHOUETTE_UV_FIT, включая guards нормальных уравнений.
  K/silhouette.py:264-296,459-468,530-549.
  Центрировать x,y и F=(s,r), но пока не делить F на scale*w.
  D=Sxx*Syy-Sxy^2; Nx_j=Rx_j*Syy-Ry_j*Sxy; Ny_j=Sxx*Ry_j-Sxy*Rx_j.
  R_ji=Fc_ji*D-Nx_j*xc_i-Ny_j*yc_i.
  P_i(w)=R_ui^2+R_vi^2-tau^2*(scale*w*D)^2=0, для всех вершин i.
  Здесь степень <=10 (centered LSQ, affine operands); D=0, w=0, scale-selection,
  normalized determinant<=0 и nonfinite — отдельные guards, а не разрешение
  умножать неравенство на неизвестный знак. Никакого общего Q(sqrt(q))-решения.
  max residual <=tau значит ВСЕ P_i<=0. Идентификатор limiting vertex сохраняется.
  Для продукта требуется fp-envelope всей процедуры; без неё full/refusal.

E09 SILHOUETTE_MERGE_CHORD / AREA_ORDER / PLANE_VALID.
  K/silhouette.py:228-245,455-458,492-509.
  Newell N degree<=2; ((p-centre)·N)^2-tau_chord^2*|N|^2=0 (<=6);
  |N1|^2-|N2|^2=0 (<=4) для выбора большей грани; |N|^2=0.
  Проверяются меньшая грань относительно большей и union относительно своей
  плоскости. Использовать current post-merge ring; ошибка float => band.

E10 SILHOUETTE_VERTEX_CHORD / PROJECTION_CLAMP.
  K/silhouette.py:253-261,650-655.
  e=end-start,d=p-start. Для 0<t=(d·e)/|e|^2<1:
  |d×e|^2-tau_chord^2*|e|^2=0 (<=4).
  Внешние ветви: |p-endpoint|^2-tau_chord^2=0 (<=2).
  Guards |e|^2=0, d·e=0, d·e-|e|^2=0; не забыть весь accumulated removed run.

  K/silhouette.py:575-619,656-662,685-698.

E12 SILHOUETTE_ORDER / READ-WRITE DEPENDENCIES.
  K/silhouette.py:398-406,434-444,563-571.
  Сортировка по float dihedral и sag. Реальные равенства углов можно свести к
  dot/cross полиномам с обязательным контролем квадранта; sag ties — рациональные

E18 HOST_WELD_CLASS / WALL_PARTNER / MITER / UV_SEAM (вне kernel table).
  H/envelope_production_weld.py:141-194,210-244,292-398,650-660.
  source weld/twin по float.hex и UV seam по float tuple equality могут менять
  connectivity даже при неизменном kernel batch. Exact identical trajectories
  плюс одинаковое округление => STATIC; случайное равенство округлённых чисел
  не даёт непрерывного интервала. Direction test: |d×h|^2-sine^2*|d|^2*|h|^2=0
  (<=4) и d·h=0; normal blend clamp, zero normal, pivot/residual/miter-limit
  требуют interval evaluation фактической host procedure.
  Для constant normals часть STATIC. Для developable normals — нелинейная
  функция width, не общий rational/Q(sqrt(q)) закон. Первая поставка:
  пересчитывать host assembly из точного нового batch, а не сертифицировать
  весь miter сразу; это убирает kernel materialize cost без ложной точности.

Не независимые width-события: базовый station plan, source triangulation,
frames/density supports и surface admission при фиксированной preparation.
Их invalidate по selection/source revision/law/offset/stretch/density change.
Фильтр, который только ускоряет exact predicate и при сомнении уступает ему,
не требует нового геометрического события, но учитывается в budget proof.
Внутреннюю Blender triangulation ngons тоже нельзя считать замороженной:

5. РЕАЛИЗУЕМАЯ АРХИТЕКТУРА

5.1. Локальные guards вместо полного перечисления всех будущих ширин.
Холодный/промахнувшийся full run записывает deterministic decision tape.
Следуем ровно текущей ветви исполнения; неизменность всех прочитанных решений
доказывает повтор той же ветви индукцией. Все ранние отказы и ранние exits
записываются. После ближайшего события делаем новый full run и новый tape.
Нет нужды заранее строить весь деревообразный набор возможных future merges.

EventTableV2 хранит существующие coverage events и lazy guard records:
  {kind, site_id, operand_expression_ids, exact_polynomial_or_fp_program,
   root_isolator_or_uncertainty_band, comparison/equality_side,
   preparation_generation, decision_trace_digest}.
CertifiedWindow={open_low,open_high,limiting_events,proof_scope,unresolved=[]}.
Окно локально для данной ветви, хоть сама функция guard не зависит от anchor.
Предикат, для которого нет доказательства, сужает допуск до full/refusal.
Одновременные exact roots — atomic unordered semantic batch; overlapping
uncertainty bands объединяются как запрещённый для cache регион. w=0 отдельный
refusal. AT_EVENT не превращать в эвристическое w+epsilon.

Сначала bounded horizon около current width, interval sign proof без поиска
далёких корней; при успехе постепенно расширять. Не всё дерево корней нужно
вычислять во время drag. Горизонт — граница доказательства с именем
PROOF_HORIZON_END, не фиктивное геометрическое событие.

5.2. Worker cache и независимый host cache.
Identity: preparation content fingerprint + code/native/policy/schema version
+ output laws + interval proof digest + canonical structure digest.
Основной lookup по preparation и width, structure digest — значение найденной
записи и проверка, а не неизвестный до вычисления аргумент запроса.
Record содержит immutable topology, provenance recipes, exact operand DAG,
координатные/UV-numerator laws, guard tape, current bounds, budget proof,
current-width relabel/counter recipes. Publish только целую verified запись.
Два-три соседних окна на домен, reverse drag возвращается в уже известное окно.
Byte-bounded LRU считает resident bytes/arrays/DAG, а не только исходный pickle:
H/envelope_worker_store.py:32-34 ограничивает 32 MB ПИКЛОВ, не полный RSS.
Eviction/worker restart => named miss; worker-affinity и generation исключают
обращение к потерянной записи. Никаких product-global mutable geometry caches.

PARAMETRIC memo из rust/drag-quick переиспользуется через общий certificate
provider. Не дублировать его вычисление; не принимать memo hit как доказательство
structure. Parent scan reuse остаётся ниже input invalidation, scheduler использует
его подготовленный manifest. Другая ветка/папка не изменялась; интеграционный тест
обязателен после её merge, исходить из отсутствия конфликта нельзя.

5.3. Оценка на каждом кадре.
Exact reference: alpha_text -> Fraction; evaluate X,S,R через exact operands,
затем UV law и ТОТ ЖЕ enclosure_midpoint/sqrt_sum_binary64 (K/lift.py:37-84).
Важно сохранить src-host rebind/follower constants, normal laws, current IDs,
orientation и diagnostics, не брать exact_positions0 как готовые host позиции.
Native bulk evaluator возвращает компактные positions/UV, а не новый pickle
всей подготовки/GeometryBatch. При постоянной структуре topology не пересылается.

Ускоренный float evaluator может называться exact только если interval filter
доказывает тот же конечный rounding/mesh value; иначе exact fallback. Обычный
P0_double+s_double*dw — лишь NUMERIC_ROUNDING_APPROXIMATION с явным bound,
даже при доказанной topology. Не смешивать этот статус с FIELD_EXACT или
FULL_ANSWER_IDENTICAL. Отсутствие periodic reconciliation относится только к
полностью доказанной части; shadow verification остаётся инструментом разработки.

5.4. Host scheduling и реальный меш.
Для каждого domain хранить текущее окно; глобальные min/max endpoint queues
со stale-entry generation, а при смене направления — противоположную очередь.
O(D) простой просмотр для ~1000 доменов тоже допустим до измерений: heap не цель.
Внутри окна не dispatch full domain, обновить числовые массивы реального меша.
На пересечении endpoint отправить только dirty domains + host dependency closure
(weld partner/shared seam), предварительно объединить одинаковый width request.
Worker computes latest requested width; устаревший ответ discard по generation.
Большой прыжок может сразу вызвать full на target, а не replay всех исторических
событий; receipt перечисляет пройденные известные границы и RESEED_AT_TARGET.
Предварительно считать соседнее окно лишь при наличии свободного worker; это
ускорение, не условие корректности и не повод отбирать всю мощность у drag.

Перед публикацией complete frame проверить: все contributions рассчитаны для
одной width/generation, host weld/seams valid, mesh layout совпадает. Пока нет —
оставить последний complete frame, PENDING_EXACT_EVALUATION; не собирать соседние
патчи из разных width. Лёгкие графические подсказки могут жить отдельно.
На event структура локально изменилась: пересобрать host mesh image одним
атомарным применением. У bpy нет обещания дешёвой локальной перестройки topology;
это отдельная цена, измерить p95/p99. Cancel возвращает исходное состояние;
release/commit и cold в первой поставке продолжают существующий full path.

5.5. Developable/unfold.
PARAM_NON_AFFINE_DEVELOPABLE_OFFSET остаётся отдельным статусом.
Kernel batch можно ускорять только при его собственных доказанных laws.
На exact кадре пересчитывать angle-weighted normals, wall partner и miter
существующим кодом из новых позиций; обновлять всю dependency closure.
Если это не укладывается в бюджет кадра — named pending/full, не скрытое
замораживание normals под словом exact. Существующий approximate preview
может оставаться отдельно, с собственным статусом; его не включает certificate.

8. РИСКИ И STOP RULES

- Любое необъяснённое отличие на заявленном certified hit: STOP допуска этого
  пути немедленно, LAZY_VERIFY_MISMATCH, fallback и воспроизводимый receipt.
  Никакого «подправить раз в N кадров» для режима, названного exact.
- Неполный trace, неизвестный function class, неразрешённый корень, determinant
  около нуля, недоказанная fp-ошибка/order/budget: named refusal; не расширять
  окно по успешной случайной выборке. Не подбирать safety factor экспериментом.
- Не менять силуэт, tolerance, tie-break, UV seam/weld или resource semantics
  ради cache hit без отдельного решения владельца. Это меняет ответ.
- Высокая доля fallback/слишком короткие окна/дорогая certification: измерить
  wall contribution, продолжить использовать quick wins, не включать default.
  >15% cold overhead или p95 выше выбранного frame budget => пересмотр дизайна.
- RAM: bounded bytes/RSS ledger и eviction; 32 MB pickle != 32 MB resident RAM.
  Disk <1.5 GB на любом доступном диске => немедленно остановить новые расчёты.
- Blender только -b frozen_scene --python-exit-code 1 --python script;
  не сохранять .blend, не обращаться к quit/autosave, не останавливать чужие PID.
- Никакого заявления «realtime доказан» до GUI acceptance владельца.
